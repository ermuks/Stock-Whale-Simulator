# Codex 작업 지시서 | DonDon 태블릿 UI 전면 개편
**사용 모델: Astra 6 Medium**

## 목표
첨부된 `References/01_Assets.png`, `02_Order.png`, `03_Company.png`, `04_AutoTrade.png`를 동일한 디자인 시스템의 시각적 기준으로 삼아, 현재 Unity 프로젝트의 두 World Space 태블릿 UI를 실제 플레이 가능한 수준으로 전면 개편하고 기존 기능의 누락·불일치·오류를 보완하라. **그림을 UI 배경으로 붙이지 말고**, UI TextMeshPro SDF / Unity UI Image, Button, ScrollRect, LayoutGroup 등 실제 동적 컴포넌트로 재구현하라.

## 사용 가능한 에셋
- `Atlases/DonDon_Solid_Icons_256.png`: 흰색 솔리드 아이콘 8열×6행 256px 셀, RGBA Alpha 배경 0.
- `Atlases/DonDon_Solid_Icons_128.png`, `_64.png`: 동일 순서의 경량 버전.
- `Docs/IconManifest.json` 및 `IconIndex.csv`: 아이콘명, 위치, 순서.
- `Docs/DesignTokens.json`: 색·간격·상태 규격.
- `Docs/GameTimeAndLogic.md`: 시간·자산·주문·기업 계산과 상태 불변조건.
- `Icons_256/`: 개별 아이콘을 사용해야 할 때만 이용.

## 시작할 때 반드시 할 일
1. Unity 씬/프리팹/스크립트/현재 두 태블릿 Canvas/입력·포커스 구조/게임 시간 시스템/계좌·주문·기업·자동 매매 시스템을 먼저 조사한다.
2. **기존 파일과 실제 데이터 흐름을 확인한 뒤** 새 UI가 기존 도메인 모델과 연결되도록 구성한다. 이름만 비슷한 신규 매니저를 중복 생성하지 않는다.
3. 현재 가능한 기능, 미구현·오류·상태 미연결 기능, 시안과 차이 나는 화면을 간단하게 체크리스트화하고 중요도 P0/P1/P2로 분류한다.
4. 가능하면 기능을 유지한 채 레이아웃·스타일을 먼저 교체하고, 부족한 동작을 검증 가능한 작은 단계로 구현한다. 사용자가 추가 지시하지 않아도 프로젝트 범위 안의 필요한 개선을 완료한다.

## 디자인 방향 (가장 중요)
- **Dark Minimal + Solid White Icons + Flat UI**. 어두운 차콜/청회색 배경, 흰색 솔리드 아이콘, 활성/중요 액션에만 청록. 색은 런타임 `Image.color`로 적용.
- 이미지 레퍼런스의 정보 구조를 참고하되 그대로 복제하며 빽빽하게 만들지 말 것. 3D 일러스트, 광택, 네온, 불필요한 설명문, 장식용 카드, 작은 글씨는 사용하지 않는다.
- `Docs/DesignTokens.json`을 기본값으로 사용하되, 실제 기기 월드스페이스 렌더링에서 가독성이 우선. 배경 카드/테두리를 무분별하게 추가하지 않는다.
- 1초 안에 중요한 숫자와 다음 행동을 확인할 수 있게. 카드 개수보다 **명도·크기·정렬·여백**으로 위계를 만든다.
- 주요 값은 1~2개만 크게, 나머지는 목록 또는 상세 이동으로 노출. 단일 화면에 모니터 차트·호가 데이터를 다시 표시하지 않는다.
- 아이콘으로 의미가 불명확하면 짧은 레이블을 함께 표기. 직관적 기능에는 중복 설명 문장 금지.
- 금액/수량 열은 우측 정렬, Tabular Numerals, 원 단위 정수, 자리수 증가에도 위치 고정. 한/영/일 TMP 폰트 폴백, 레이아웃 확장/축약 검증.
- 주요 버튼 최소 높이 52, 일반 버튼 44, 입력 48, 목록 행 54(소스 기준), 8px 공간 단위. 실제 태블릿 크기에서 터치 판정과 읽기 크기를 점검.
- **한 페이지의 주 실행 버튼은 1개만 시각적으로 최우선**. 경고·비활성·실행 중·성공/실패·잠금 표시를 구별.

## 필수 화면
**태블릿 1: 기본 계좌**
- `자산`: 핵심 4개 수치(보유 주식 평가금/평가손익 및 수익률/주문 가능 현금/총자산). 보유 목록은 4열: 종목명+수량 / 현재가+평균가 / 평가금 / 손익+수익률. 행을 탭하면 종목 상세·주문으로 이동. 미보유 간결 빈 상태.
- `주문`: 매수·매도 Segmented Tab, 별도 주문 유형, 같은 크기 가격·수량 필드, 균등 비율 버튼, 예상 금액·가용 자원, 실행 버튼, 여러 미체결 주문·행별 취소. 새 주문은 미체결 존재 여부와 독립적으로 가능. 예산 초과 시 실행 불가 및 짧은 사유.
- `내 기업`: 기업 평가액, **기업 운영 현금**, 일 매출·순이익·지분율, 배당/재투자/비축 정책, 설비 확장/영업 확대/기술 연구의 효과·비용·기간·진행 상태. 상장 4조건과 신청 버튼. 기업 현금과 개인 현금을 섞지 않는다. 상장 전 기업가치만, 상장 후 실제 시장 시총 별도.
- `기록`: 거래, 정산, 뉴스, 기업 정보는 관련 하위 화면으로 정리하고 첫 화면에 전부 밀어 넣지 않는다.

**태블릿 2: 작업 계좌**
- 기본 계좌와 공통 색/컴포넌트 규격, 하지만 자산·현금·포지션·주문은 별도.
- 기본 계좌 **총자산이 100,000,000원을 초과**하기 전까지 잠금. 잠금 화면에는 자물쇠 아이콘만 표시.
- `자동 매매`: 종목 선택, 스프레드 범위 단일 슬라이더, 예상 매수·매도 가격, 가용 현금·가용 주식, 매매 시작/취소, 실제 미체결·체결·손익 정보. 진행 중 중복 실행 금지.
- `가짜 뉴스`: 자동 매매와 구분된 잠금·해금 하위 페이지. 기존의 실제 10분 재사용 제한을 유지하면서 **화면에 표기하는 시간은 게임 시계로 환산**. 시안처럼 메인 자동매매 페이지에 상세 입력을 같이 넣지 않는다.

## 시간: 최우선 공통 규칙
**화면에 나오는 시간은 전부 게임시간이다.** 상단 `DAY n HH:mm`, 주문 접수·체결·취소, 투자 완공/잔여, 자동 매매 실행 경과·최근 갱신, 정산 기록, 뉴스와 재사용 대기 표시 전부 게임 시간 서비스의 단일 기준으로 바인딩하라.
- 시스템 로컬 시간(`DateTime.Now`, `DateTime.UtcNow`)을 UI 표시값으로 사용 금지. `Time.time`을 독립적인 사용자 표시시계로 사용 금지. 임의 하드코딩 타임스탬프 금지.
- 시간 배속 기능을 추가하지 않는다. 기존 GameClock과 세이브/로드/일시정지 정책을 확인하고 일관된 표시를 보장한다.
- 기존 '가짜 뉴스 실제 10분 쿨다운'은 유지해야 한다. 게임시간과 현실시간이 일치하지 않을 때 표현/환산 정책을 먼저 점검하고 **표시만 게임 시간**으로 통일하되, 기능 동작 시간을 조용히 바꾸지 말 것. 모순이 있으면 보고에 명시.

## 핵심 로직 보완 (UI 작업에 필요할 경우 구현)
- 계좌별 현금·포지션·주문·예약자산·손익 분리. 현금 부족/중복 주문/일부체결/개별 취소 시 원장과 UI 일치.
- 실제 원화 주문 비용 `가격 × 수량 + 수수료`를 기준으로 유효성 판단. 예약된 매수자금 및 매도주식은 가용 자산에서 제외. 변경 이벤트 이후 자동 갱신.
- 기업 투자 비용 기업 자금에서 1회 차감, 프로젝트 완료 효과 1회 적용, 배당금 개인 계좌에 실제 입금하는 시점 분리. 정책 합 100% 유지.
- 상장 조건 `평가액 >= 5천만 / 누적 흑자 >= 3 / 확장 완료 >= 2 / 미지급 비용 0`. 상장 후 시가총액 계산은 실제 종가 × 발행 수량이며 기업 평가액과 동일시하지 않는다.
- 자동 매매는 작업 계좌의 미예약 잔고 내에서 주문하고, 상태/체결/취소가 실제 주문 엔진 및 로그에 바인딩되어야 한다.
- 신규 기능을 땜질용 가짜 데이터로 완료 처리하지 말 것. 참조 이미지 내 수치와 타임스탬프를 하드코딩 금지. 불일치한 예시 수치는 그대로 복제하지 않는다.

## 작업 순서
1. 구조·기능 조사와 파일별 변경 계획 → 2. 공통 테마/아이콘/상태 컴포넌트 → 3. 기본 계좌 자산·주문 → 4. 기업 경영·상장 → 5. 작업 계좌 잠금·자동매매·특수기능 → 6. 게임시간 통일·다국어·성능·회귀검증.
- 기존 3D 태블릿 모델, 배치, 입력 라우팅, 카메라, World Space Canvas의 정합성은 유지하고, 필요한 UI 내부 계층만 변경.
- 변경 시 기존 프로젝트의 스크립트 이름/클래스/함수를 먼저 확인하고, 어떤 스크립트의 어떤 함수·컴포넌트를 변경했는지 보고.
- C# 코드 스타일: `if`의 즉시 `return`/`continue`/`break`는 다음 줄에 한 줄 블록 `{ return; }` 형태. 그 외 `if/for/while` 중괄호 생략 금지. 불필요한 빈 줄과 무의미한 줄바꿈을 피함. 새 스크립트는 파일 전체가 완결되어야 함. 기존 스크립트 수정 덩어리가 3개 초과면 함수 단위로 원본·수정본의 변경 의도를 비교하여 보고.
- 자동테스트 가능 영역은 로직 회귀테스트를 추가하고, Unity 플레이모드에서 실제 입력/스크롤/버튼 클릭/텍스트 표시를 검증.

## 필수 수용 테스트
- 첫 실행/미보유/현금 0/미체결 여러 건/주문 부분체결/계좌 전환/재진입/저장 후 재로드.
- 정확히 1억 원이면 태블릿 2 잠김, 1억 원 초과 시 해금.
- 적립금·기업 현금·배당이 다른 계정으로 잘못 계산되지 않음.
- 상장 4조건 각각 미충족일 때 버튼 비활성, 충족 시 활성.
- 자동 매매 시작/중지/재시작과 예약 주문 자원 반환이 일치.
- 모든 표시 시각이 GameClock과 일치, 세이브/로드 이후 타임스탬프 유지.
- 한국어/영어/일본어, 1600×900/1920×1080, 기기 월드스페이스 실제 시점에서 텍스트/터치/레이아웃 무너짐 없음.
- Icon Atlas 알파 0, 아이콘 누락 없음, 가로세로 스케일 늘어짐 없음.
- 기본 화면에서 중요 상태 파악에 1초 이상 읽게 만드는 중복 텍스트 없음.

## 완료 보고 형식
1. 변경·신규 파일 및 주요 함수/프리팹 위치.
2. 4개 화면 구현 결과와 기능 연결 상태(완료/부분/미구현, 미구현 이유).
3. 게임시간 데이터 출처와 가짜 뉴스 쿨다운 환산 정책.
4. 테스트 실행 결과(수치·실패 원인) 및 씬 실제 스크린샷.
5. 원본과 차이가 남은 부분, 향후 꼭 필요한 개선안.
