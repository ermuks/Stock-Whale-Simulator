# DonDon UI 데이터·시간·상태 계약

## 1. 모든 시각 표시 = 게임 내부 시간
- `DAY n HH:mm` 게임의 날짜·시각.
- 주문 접수 / 체결 / 취소 / 뉴스 / 정산 이벤트 시각 모두 같은 GameClock의 타임스탬프.
- 기업 투자 소요·잔여·완공 시각은 동일 시계에서 파생. `2일`, `1일 남음`도 게임 일자 기준.
- 자동 매매 실행 경과 / 갱신 시각 / 재사용 대기 화면은 게임시간으로 표시.
- `DateTime.Now`, `DateTime.UtcNow`, 운영체제 시간, `Time.time`을 화면에 그대로 표시하지 않음.
- 게임의 시간 배속은 없음. 기존 시간 서비스가 있으면 재활용하며 새 독립 카운터 중복 생성 금지.
- 저장/불러오기/일시정지/장기간 플레이 중에도 표기가 이어져야 함.

### 가짜 뉴스 쿨다운 주의
- 기존 기획: 재사용까지 **실제 시간 10분**.
- 이번 수정: **표시되는 시간은 항상 게임시간**.
- 게임 시계와 실제 시간의 배율/일시정지 규칙을 먼저 확인해, 10분 쿨다운을 기존 의도대로 유지하면서 UI는 게임시간 기준 해제 시각 또는 게임시간 환산 남은 시간으로 표시한다.
- 두 시간축이 일치하지 않으면 원래 쿨다운 규칙을 마음대로 바꾸지 않고, 정책 충돌과 선택안을 완료 보고에 명확히 적는다.

## 2. 기본/작업 계좌는 별개
- 자금, 보유수량, 평균가, 수익, 예약/미체결 주문은 반드시 계좌별 분리.
- 작업 계좌 잠금 화면은 `lock` 아이콘만 표시. **기본 계좌 총자산 > 100,000,000원**일 때 해금, 정확히 1억 원은 해금 X.
- 계좌 간 데이터가 섞이지 않는지 시나리오 테스트.

## 3. 주문과 계산
- 주문 금액 = 원 단위 가격 × 주 수량. 임의의 소수점 원화 금지.
- 매수 가능액은 열린 매수 주문의 예약 금액 및 수수료를 차감해야 함.
- 매도 가능 수량은 열린 매도 주문에 예약된 보유수량을 차감해야 함.
- 새 주문은 기존 미체결 주문이 있어도 가능(잔여 자원 범위).
- 자원 부족 시 실행 버튼 비활성 + 짧은 이유 표시. 미체결 개별 취소 시 예약 자원 반환.
- 여러 주문·부분 체결·취소·실패 모두 실제 주문 엔진 상태 반영.
- 자산 = 계좌별 현금 + 보유주식 평가금. 손익은 원금·평균가 및 보유수량을 기준으로 계산.

## 4. 기업 운영
- 개인 계좌 현금과 기업 현금 분리, 비용은 기업 현금에서만 차감.
- 순이익과 플레이어 배당 수령액 구별. 배당/재투자/비축 배분 합계 100%.
- 완공 중인 프로젝트는 진행 상태를 표시하고 중복 비용 차감/완공을 방지.
- 상장 조건: 평가액 ≥ 50,000,000 / 누적 흑자 결산 ≥ 3 / 완료한 사업 확장 ≥ 2 / 미지급 비용 0.
- 상장 전에는 기업 거래 종목 없음. 상장 후 가격과 거래를 실제 투자자 봇이 결정.
- 기업 평가액 ≠ 시가총액. 마감 시총 = 실제 종가 × 발행 주식수.

## 5. 자동 매매
- 종목과 스프레드 값으로 예상 주문가를 보여 줌. 매수/매도 예상가 모두 원 단위 정수.
- 자동 매매 주문도 작업 계좌에 실제로 있는 미예약 현금·보유수량만 사용.
- 중복 시작 방지. 취소 시 실제 열린 자동 매매 주문 처리, 예약 자원 정산.
- 진행 현황은 상태(대기/접수/일부체결/체결/취소/실패), 주문 수량, 실제 체결 기록에 근거.
- 화면은 편집 가능한 값과 읽기 전용 결과를 명료하게 구분.

## 6. 상태·비주얼
- 활성: 청록, 비활성: 회색 + 입력 불가, 진행: 청록+남은 시간, 완료: 흰 체크 / 성공 청록, 실패: 주의 아이콘+간단 사유.
- 수익 빨강, 손실 파랑 (한국 시장 관습). 중립값은 무채색.
- 상장 버튼은 4가지 요건 모두 충족해야 활성화.
- 자동 매매 실행 중 `시작` 버튼 비활성화(혹은 `중지`로 모드 전환), 중복 실행 요청 무시.
- 주문 금액 범위 초과 시 버튼 비활성, 화면 내 계산 결과는 유효한 값으로 표시.
