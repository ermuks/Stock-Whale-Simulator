평가와 와이어프레임에서 반영한 내용
- 현재가, 등락률, 평단, 보유 수량, 평가손익을 주문 설정과 함께 표시합니다.
- 매수/매도 방향과 지정가/분할 설정을 분리합니다.
- 설정 단계는 미제출 상태이며, 주문 내용 확인 이후 별도 최종 제출을 제안합니다.
- 예상 값은 5,390원에 전량 체결되는 경우로 명시하며, 실제 체결을 보장하지 않습니다.
- 두 태블릿에서 선택 종목과 현재가를 공통으로 유지합니다.
- 사건은 출처·확인 여부·관측된 시장 반응·다른 참여자의 발언으로 구분합니다.
- 사건의 호재/악재를 정답처럼 판정하거나, 봇 내부의 신뢰·배신 수치를 공개하지 않습니다.
- 같은 손익 요약을 반복하는 대신 주문별 체결 시각, 가격, 수량, 잔여량을 제안합니다.
- 경영 기능이 잠겨 있을 때는 현재 지분과 해제 조건만 보여주고 조건 보기로 접근합니다.
- 휴대폰의 받기/거절/화면 닫기가 무엇을 하는지 각 버튼 주변에 명시합니다.
- 이전 연락 기록은 현재 미확인 발신자와 같은 사람의 기록이라고 연결하지 않습니다.

원래 코드에서 확인한 동작
- TradingOperationController.Prepare: 준비 시점의 가용 현금에 BudgetFraction을 곱해 예산을 고정합니다.
- 예산 50,000원은 준비 당시 1,000,000원의 5%입니다. 현재 현금 970,000원의 5%라는 뜻이 아닙니다.
- PhoneCallController.Lower: 화면/그립을 내리며 Ringing을 거절 처리하지 않습니다.
- PhoneCallController.Decline: 현재 수신을 종료합니다.
- PhoneCallController.Ring: 알림을 생성하지만 자동으로 휴대폰 화면을 열지 않습니다.

추가 구현이 필요한 제안
- 가격·수량 직접 입력과 주문 확인 단계: 현재 태블릿의 모드 실행 버튼을 그대로 바꿔 그리기만 해서는 동작하지 않습니다.
- 사건 상세와 관련 채팅·출처 연결, 개별 체결 로그와 주문 식별자, 최근 연락 시각/상대 기록: 실제 데이터에 연결하는 작업이 필요합니다.
- 분할 설정을 바꾸는 것과 실제 실행을 명시적으로 분리하고, 최종 제출 시 잔고·예산·수량·호가 단위를 다시 검증해야 합니다.
- 이벤트 숫자와 배지는 실제 데이터가 있을 때만 표시해야 하며, 공개되지 않은 봇 상태를 추정 사실로 넣지 않습니다.
- '매수 체결 비중'은 매수 주도 체결량/전체 체결량으로 정의해야 합니다. 모든 체결에 매수자와 매도자가 동시에 있다는 점과 구분합니다.
- 실제 3D 모니터/태블릿 거리에서의 글자 크기, 클릭 영역, 긴 문자열, 입력 중 단축키 차단은 적용 단계에서 별도로 검증해야 합니다.

시안 숫자 교차 확인
준비 당시 가용 현금 1,000,000원 × 5% = 예산 50,000원
6주 × 평균 5,000원 = 사용 금액 30,000원
가용 현금 970,000원, 예치 0원, 계획 잔여 20,000원
현재 5,390원: 6주 × 390원 = 평가손익 +2,340원 (+7.8%)
전일 대비 예시: 기준가 5,160원 → 5,390원, +230원, +4.5%(반올림)
3주 × 5,390원 = 예상 주문액 16,170원
전량 체결 가정: 현금 953,830원 / 보유 9주 / 계획 잔여 3,830원
5주 입력 시: 26,950원으로 계획 잔여 대비 6,950원 초과 → 확인 버튼 비활성
6 / 10,000,000주의 기업 지분은 사실상 빈 진행 막대로 표현하며, 경영권은 50% 초과 조건을 유지합니다.
