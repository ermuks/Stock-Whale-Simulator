# DonDon 개발 기준과 단계별 로드맵

2026-11-14 사용자 지시를 기준으로 한다. 목표는 개인 투자자 → 리딩방 운영자 → 세력 → 기업 지배자 → 거래소 운영자 → 시장 지배자로의 권한 변화다. 챕터는 설명 구조이며 강제 미션 순서가 아니다. 관찰·판단·행동·반응·결과·성장 순환을 우선하며 배속은 넣지 않는다.

## 현재 구현과 빈 곳

1. **개인 투자자**: `StockManager.Economy`의 소액 시작, 실제 계좌/호가 매칭, 캔들/거래 통계, 시장 채팅이 있다. 기존 태블릿에 지정가/분할 입력, 확인, 체결 결과, 취소를 연결했다. 첫 화면에서 시작하면 기존 투자자가 운영하는 ‘새벽 관찰실’에 가입한다. `NpcLeadingRoom`이 그 투자자의 실제 주문·체결을 공개하고, 플레이어가 가격을 기존 주문 태블릿의 초안으로 가져와 직접 판단·제출한다. 자동 추종이나 수익 보장은 없다.
2. **리딩방 운영자**: `InvestorSociety`, `LeadingRoomOrders`, 심리·기억·전염·3개 방·조건부 명령은 있다. 개설 조건이 없어 시작부터 지시할 수 있었다. 이번 단위는 실제 거래 성과를 읽어 운영 권한을 얻고 직접 개설하는 경로를 연결한다. 공개 채팅과 방 관찰, 봇의 자율 대화·참여는 계속된다.
3. **시장 세력**: 신뢰/배신, 독립 자금, 자율 가입/탈퇴, 세력의 손실 기억과 정리는 있다. 실제 자금으로 거래하며 성과를 공개하는 NPC 운영 방 1개가 추가됐다. 운영자별 관계 기억, 여러 방의 경쟁·장기 연합/분열, 종목별 영향력의 검증 가능한 정의는 다음 확장 대상이다.
4. **기업 지배**: `WorldDramaDirector.Controls`의 실제 지분 50% 초과, 경영진/신사업/자금 기반 배당/지분 매입이 있다. 연결 기업 그룹, 사업별 현금흐름·회계와 기존 경쟁자의 장기 반응은 확장 대상이다. 낮은 챕터라는 이유로 실제 과반 지분의 권한을 막지 않는다.
5. **거래소 설립**: 미구현. 현재 `Stock.orderBook`은 종목당 단일 시장이다. 설립 버튼만 추가하면 자산·주문·가격의 정합성을 깨뜨릴 수 있다.
6. **거래소 성장**: 미구현. 시장별 호가, 투자자/기업의 자발적 선택, 유동성 비용, 수수료 회계, 실제 주문에 의한 가격 연결이 필요하다.
7. **시장 장악**: 미구현. 점유율·지급능력·체류율 등 실제 결과로 경쟁하고, 자산과 미체결 주문을 처리한 뒤 퇴출/폐쇄되어야 한다.
8. **시장의 지배자**: 미구현. 상장/정지/폐지 권한, 정책에 대한 시장 이탈·신뢰 반응, 누적 결과 기반 엔딩과 자유 계속 플레이가 필요하다.

## 이번 플레이 단위

- 실제 주문과 확인 흐름: `DeviceOrderSession`이 기존 `Trader.BuyLimit/SellLimit` 및 `OrderBook.CancelOrder`를 호출한다. 현금·주식·가격을 UI에서 만들지 않는다. 미제출 분할분은 가짜 예치로 계좌에 기록하지 않고 별도로 표시한다. 제출할 때마다 자금과 재고를 재확인한다.
- 실제 결과 관찰: `DeviceMarketJournal`이 공개 뉴스와 `OnMatchedTrade`를 읽는다. 매수 주도 비중은 발생 직전 60초의 매도 호가를 소진한 체결량/전체 체결량이다. 사건과 채팅의 연결은 사건 ID가 일치할 때만 표시한다.
- 첫 권한 변화: `PlayerProgression`은 실제 체결 거래대금과 원가를 제외한 실현손익으로 운영 자격을 계산한다. 평가이익이나 버튼 클릭 수로 권한을 주지 않는다. 조건은 `Resources/Progression/PlayerProgression.json`에서 조절한다. 권한 획득 뒤에도 봇은 기존 심리/자금/경험에 따라 초대와 지시를 독립적으로 판단한다.
- 기존 거래소 대응: `IncumbentExchangeAI`는 주기적으로 실제 플레이어 상태를 관찰한다. 지능은 관찰 간격으로 표현한다. 대응은 기존 거래소 방어 슬롯, 재고·현금·위험 제한 안에서 실행하고, 관찰 주기와 주문 빈도 제한을 분리해 빠른 관찰이 대량 주문으로 변하지 않게 한다.
- 기존 기능: 자동 운용/자산·뉴스/보유 상세/기업 경영 탭과 전화 동작을 유지한다. 장치의 원래 3D 위치와 Canvas 루트·카메라를 보존한다.

## 개발 우선순위와 통과 조건

### 진행 단위 A: 지속 가능한 첫 플레이 루프

첫 화면→NPC 방 가입→실제 주문 관찰→태블릿 주문 검토/제출→실현 성과 확인→내 방 개설까지 기존 Canvas와 시스템을 연결했다. 기존 계좌를 가진 운영자 1명과 기존 사회 시스템의 자율 가입·대화·퇴장을 재사용한다. 플레이어 방 1~3과 NPC 방 4는 소유권·진행 상태·채팅 기록을 분리하며, NPC 성과를 플레이어의 실현손익·신뢰로 전염시키지 않는다. 작은 시작 안내는 닫을 수 있고 거래나 성장을 강제하지 않는다.

관찰만 하는 플레이에서도 시장과 대화가 유지되어야 한다. 이번 단위의 정상 속도 단기 실행과 격리된 실제 체결 검증을 장기 밸런스 검증으로 해석하지 않는다. 운영자 신호의 유용성, 첫 성과 달성까지 걸리는 시간, 여러 시장 시드에서의 이탈/관전 재미가 다음 관찰 대상이다. 해금 수치는 현재 거래대금 10만 원과 누적 실현손익 5천 원이며 최종 밸런스는 아니다.

### 다음 단위 B: 전체 월드 저장/복원

현재 전체 게임 저장은 없다. 진행 상태 캡처/복원 계약만으로 게임 저장 완료라고 부르지 않는다. 계좌 현금·보유·원가·미체결 예치, 주문 우선순위, 시계, 상장/위험 상태, 봇 심리·기억·방·명령, 세력 관계, RNG 상태를 같은 월드 ID로 저장해야 한다. 저장 중 체결 경계를 일치시키고, 복원 전후 현금·주식 총량 및 주문 소유권이 같아야 한다. 새 경제에 이전 진행 권한만 불러오는 동작은 거부한다.

### 단위 C: 경쟁 세력과 기업 그룹

경쟁 방 운영자가 실제 자기 자본과 성과를 갖게 한다. 지지/반대 관계는 경험과 목격으로 갱신하며 강제 집단 대본으로 만들지 않는다. 기업 사업 활동에는 자금 원천과 비용·수익을 부여한다. 기업 인수는 세력 관계와 뉴스·대화의 이어지는 사건이 되어야 한다.

### 단위 D: 두 거래소의 최소 경쟁

단일 호가를 무리하게 복제하지 않는다. 종목 자산과 시장별 주문장을 분리하고, 이전 가능한 보유 주식은 동일 원장으로 관리한다. 한 종목·두 시장·소수 자율 참여자로 먼저 검증한다. 가격 추종은 실제 유동성 공급과 차익 거래로 나타나며, 플레이어 성장 단계에 따라 가격을 강제로 맞추지 않는다. 수수료는 거래자에서 거래소로 이전하는 회계다.

### 단위 E: 거래소 성장·퇴출·엔딩

상장사/회원 유치, 장기 점유율, 재정 건전성, 정책 신뢰를 경쟁 변수로 확장한다. 기존 거래소는 플레이어를 위해 강제로 패배하지 않는다. 폐쇄 시 미체결 정리와 자산 이전이 먼저다. 서로 다른 정책과 결과가 엔딩을 결정하고, 엔딩 후 같은 월드를 계속할 수 있게 한다.

## 작업과 검증 규칙

한 번에 하나의 플레이 단위를 구현한다. Unity 검증도 한 프로세스로 순차 실행한다. 이번 검증 런처는 CPU affinity 3(논리 코어 2개), BelowNormal 우선순위, job worker 1, asset import worker 1, 시간/메모리 한도를 사용한다. 장시간 밸런스 검증과 UI 캡처를 동시에 실행하지 않는다. 실패한 검증을 완료로 보고하지 않는다. 실제 카메라 가독성은 별도 패널용 가상 카메라가 아니라 `Camera.main`으로 확인한다.
