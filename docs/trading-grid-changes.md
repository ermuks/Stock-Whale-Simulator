# 거래 UI 그리드 재구성

2026-11-15. 두 계좌 태블릿의 기존 거래 화면 안에서 레이아웃과 표시만 교체했다. 기존 씬·프리팹·3D 카메라 위치를 저장하거나 변경하지 않았다.

## 화면 구성

- 상단: 종목명/티커, 현재가, 전일대비만 유지. 미니 차트·최근 캔들 설명·중복 선택 종목 문구를 제거했다. 전일 기준이 없으면 허위 상승액 대신 `—`를 표시한다.
- 왼쪽: 주문 가능 현금, 예약금, 보유/매도 가능 수량, 평균가, 평가손익. 모두 레이블/숫자/단위를 분리했다. 예약금은 실제 미체결 예약금과 아직 제출하지 않은 분할 예약금을 합산하고 주문 가능 현금은 기존 세션 값을 그대로 읽는다.
- 미체결: 매수/매도, 종목/티커, 가격, 잔량/체결 수량, 취소의 고정 열. 행을 재사용하고 기존 개별/전체 취소와 드래그·휠 스크롤을 유지한다. 빈 목록에는 `—`만 표시한다.
- 오른쪽: 매수/매도 세그먼트, 독립 주문 유형 영역, 동일한 가격/수량 행, 25/50/75/100% 버튼, 분할 옵션, 합계, 주문 후 현금/수량, 최종 제출. 현재 주문 엔진이 제공하는 **지정가**를 유지했다. 지원하지 않는 시장가 동작을 추가하지 않았다.
- 입력 초기화, 진행 상태 문구, 제출 뒤 별도의 설명형 영수증 화면을 없앴다. 분할 확인은 기존처럼 거치고, 제출 뒤에는 바로 주문 작성 화면과 실제 미체결 목록을 보여준다.
- 오류가 있을 때만 `현금 부족`, `수량 부족`, `호가 단위 오류` 같은 짧은 원인을 표시한다. 버튼명·합계와 같은 정보를 안내문으로 반복하지 않는다.
- 거래 화면을 확대해 보는 동안 HUD 단축키 안내를 숨기고 다른 화면에서는 기존대로 복구한다. 거래 화면의 중복 DAY/시간은 숨기고 기존 전역 시장 시계는 유지한다.

## 정렬과 스타일

- 기준 그리드 1600×880, 좌우 패딩32, 두 열736, 열 간격64. 실제 기존 RectTransform 크기에 비례하며 데이터 갱신 때 그리드를 다시 만들지 않는다.
- 가격/수량 입력 및 동작 버튼의 기준 높이56, 비율 버튼 너비136/간격16. 숫자 끝은 입력창 내부 패딩을 포함해 합계·예상 잔고와 정확히 같은 축에 맞췄다. 원/주/회/초는 별도 고정 열이다.
- 같은 성격의 숫자는 동일 폰트 크기와 우측 정렬을 사용한다. Auto Size는 사용하지 않는다. 큰 금액으로 바뀌어도 앵커·행 높이·주변 버튼 위치는 변하지 않는다.
- Pretendard 원형을 이용한 별도 `Trading Numerals` SDF를 만들었다. 0~9의 advance를 동일하게 하고 폭 차이는 글리프 좌우 여백으로 보정했다. 원본 본문 폰트는 변경하지 않는다. 입력/숫자 레이블/백분율 버튼에 적용하고 kerning을 비활성화했다.
- 큰 패널 배경 Sprite와 테두리를 단색 차콜로 바꾸고 얇은 구분선만 남겼다. 매수/매도 선택은 중립색이다. 실제 최종 주문만 청록색으로 강조한다. 분할 미리보기는 보조 버튼, 확인 화면의 제출은 주요 버튼이다.
- 앞 작업의 생성 PNG는 입력·버튼 표면으로 재사용했다. 새로운 장식 이미지나 안내문을 추가하지 않았다.

## 수정 위치

- `TradingOrderView.cs` 신규: `Configure` 고정 그리드, `Account/Header/Draft/Confirm` 표시값, `Numeric` 고정폭 숫자 폰트, `ShortError` 짧은 오류 표시.
- `TradingNumeralFontSetup.cs` 신규: 기존 Pretendard 소스에서 전용 정적 SDF 숫자 에셋을 생성한다. `Assets/Resources/UI/TabletControls/Trading Numerals.asset` 및 `.meta` 추가.
- `DeviceTerminalUI.cs`: `ConfigureQuickOrder` 기존 컨트롤 재배치, `Order/Header` 데이터 표시 위임, `Review/Submit` 기존 거래 제출과 분할 확인 유지. 75%도 기존 주문 가능 금액/수량 계산을 사용한다.
- `PendingOrderListUI.cs`: `Configure/CreateRow/Refresh` 고정 열·풀·정수 표시. `CancelAll`/행 취소는 기존 `DeviceOrderSession` 호출을 유지한다.
- `TabletControlStyle.Apply`: 새 거래 화면의 폰트/그리드 스타일을 기존 일괄 스킨이 덮지 않게 한다.
- `TabletAccountUI.ShowPage`, `DeskControlHints.Start/LateUpdate/ViewingOrderForm`: 거래 화면에서 중복 시계/조작 안내를 숨기고 나가면 복원한다.

신규 C# 전문과 수정한 기존 함수의 원본/수정본은 [코드 기록](trading-grid-code.md)에 있다.

## 검증

최종 실행 결과는 `Validation/Screenshots/2026-11-15-trading-grid-verified/`의 `capture.json`, `checks.txt`, `resources.json`과 PNG에 보존한다. 실제 TradeScene 플레이 모드에서 기존 게임 카메라와 UI 이벤트/Raycast, 실제 주문 엔진을 사용했다. 매매 상태는 격리한 검사 계좌·종목·상대 주문으로 구성했으며 실제 플레이어 자산이나 저장 파일에 적용하지 않았다.

최종 **60개 검사 통과**, 프로세스44.4초, 최대1872MiB, 정상 종료. 기존 시장은 정상 속도로 시작했고 실제 게임 경과는9.29초다. 검증용 계좌·주문을 장기 시장 관측으로 해석하지 않는다. 임시 촬영 C#와 `.meta`는 Assets에서 제거했으며 원본을 `Validation/TradingGrid/capture-driver.cs.txt`에 보존했다.

- 1600×900과1920×1080에서 빈 잔고/미체결, 복수 주문/부분 체결, 큰 금액, 분할 옵션/확인, 두 번째 계좌를 촬영했다. 보이는 텍스트의 overflow와 긴 안내문 잔존 여부를 검사했다. 스크롤 영역 밖의 행 클리핑은 의도한 동작이다.
- 4건 동시 주문과20주 부분 체결, 한 건 취소, 전체 취소, 분할3회 중 첫4주 제출/잔여8주 예약을 확인했다. 현금 예약과 매도 수량 예약의 독립성을 검사했다.
- 99,999,000원 × 1,000,000주 입력으로 합계 99,999,000,000,000원을 확인하고, 변경 전후 입력/합계 Rect 경계가 같음을 검사했다. 현금 부족 시 주문 버튼은 비활성화된다.
- 열 경계/버튼 높이/비율 너비, 입력 숫자와 합계 숫자의 오른쪽 끝, 숫자10종의 동일 advance, 실제 버튼 Raycast를 검사했다.
- 한 코어·BelowNormal·20fps·순차 실행. 배속 기능 없음. 씬·DeviceOrderSession·Trader·OrderBook은 작업 전 바이트 및 SHA256과 동일하다.
- 첫 촬영에서 헤더 현재가의 높이 부족을 발견해 수정했다. 중간 검사도 보존했다. 스크린샷만 보고 통과 처리하지 않고 TMP overflow 실패를 수정한 뒤 다시 실행했다.
- 런타임/에디터 C# 컴파일을 통과했다. 기존 폐기 예정 API·필드 숨김·참조 비교 경고는 남아 있다. 거래/씬 보존 해시는 `Validation/TradingGrid/preservation-proof.json`, 최종 정리 뒤 컴파일 출력은 `compile-after-cleanup.txt`에 기록한다.

한계: 긴 종목명은 고정 열 안에서 말줄임 처리한다. 이번 검증은 UI와 주문 경로 회귀 검사이며 장시간 시장 균형이나 사람의 장시간 마우스 사용성 검사를 대신하지 않는다.
