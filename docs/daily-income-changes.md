# 장 마감 회사 수익과 리딩방 이용료

2026-11-15. 기존 거래소·조건부 주문·봇 심리·계좌·장 전환을 연결한 구현이다. 초기 5천만 원과 비상장 개인 회사 이름을 정하는 시작 화면을 유지하며, 회사 수익과 회원료로 다음 거래의 자금을 마련할 수 있다.

## 플레이 흐름

- 시작 화면에서 회사 이름을 2~20자로 입력한다. 기본값은 ‘내 작은 회사’다. 이 이름은 개인 사업체의 이름이며 새 상장 종목이나 지분을 만들지 않는다.
- 회사 수익은 실제 장 마감마다 250,000원, 기본 계좌로 한 번 입금된다. 자산에 비례해 늘지 않으며 오프라인·일시정지 중 추가 정산하지 않는다. 초기 5천만 원의 0.5%에 해당하고, 기본 수입만으로 5천만 원을 더 모으려면 200번의 장 마감이 필요하다.
- 실제 매매 성과로 리딩방을 연 뒤 오른쪽 채팅의 ‘내 리딩방 → 이용료’에서 **다음 장** 하루 요금을 정한다. 처음은 무료다. 금액은 원 단위 정수이며 0~1조 원이다. 중간에 값을 바꿔 이미 결제한 회원에게 추가 청구하지 않는다.
- 첫 회원은 기존대로 플레이어가 직접 초대한다. 무료일 때 기존 첫 초대 가입 규칙을 유지하지만, 유료 초대는 가격이나 자금 부족으로 거절할 수 있다. 첫 초대 실패 시 초대 자격은 소비되지 않는다.
- 가입한 봇의 주문 가능 현금에서 하루 이용료를 예수금으로 옮긴다. 같은 장에 나갔다 돌아와도 두 번 청구하지 않는다. 한 번 사용한 이용권은 중도 퇴장해도 환불하지 않는다.
- 다음 장의 시장·리딩방 활동이 재개되기 전에 회원이 새 가격으로 갱신을 판단한다. 거절하면 탈퇴하고, 미체결 매매 지시는 기존 이탈 처리로 연결한다.
- 장 마감 때 회사 수익과 실제 걷힌 회원료가 기본 계좌로 들어온다. 1번 태블릿 ‘대시보드 → 정산’에서 회사 수익, 회원료, 당일 실현 매매손익, 마감 총자산, 최근 정산을 확인한다.

## 경제와 심리 연결

`DailyIncomeLedger`는 이용권·예수금·정산 이력만 관리한다. `DailyIncomeController`가 기존 실제 계좌와 시장 전환을 연결하고, `DailyIncomeUI`는 표시와 사용자 입력만 담당한다.

- 이용료: 봇 현금 감소 → 별도 예수금 → 마감 후 기본 계좌 증가. 회원료를 새로 생성하지 않는다. 회사 수익만 고정된 외부 사업 수입이다.
- `PlayerAccounts.Available(bot)`을 사용해 미체결 매수 주문에 묶인 예약금은 건드리지 않는다.
- 가격 수용 여부는 현재 가용 현금, 평가자산, 탐욕·공포·신뢰·배신감·정보 신뢰 성향, 과거 회원료 차감 후 성과를 사용한다. 같은 봇·같은 날의 가격 성향은 고정되어 재초대만 반복해 재추첨하지 못한다.
- 신뢰·배신감 100 초과 값은 기존대로 유지하되 요금 계산에는 100까지만 넣는다.
- 첫 번째로 완료된 해당 장의 플레이어 리딩방 거래 경험에서 하루 이용료를 한 번 차감한다. 실제 체결 원가·매매 수량은 변경하지 않고 **심리 평가용 경험 원가**에만 더한다. 이후 완료 거래에는 다시 공제하지 않는다.
- 한 번도 거래 경험에 공제되지 않은 이용료는 마감에 별도 `ROOM_FEE` 기억으로 남긴다. 비용/평가자산 비율로 작은 배신감 변화를 주며, 소액 이용료를 투자금 전액 손실로 처리하지 않는다.
- 재가입 가격 판단용 실현 순성과는 해당 장 완료 거래들의 손익에서 하루 이용료를 한 번 뺀 값이다. 최근 값은 이전 값과 반씩 섞는다. 미실현 수익은 성공 실적으로 간주하지 않는다.
- 회사 수익·회원료는 리딩방 개설 조건의 실현 매매손익이나 거래대금에 포함되지 않는다.

## 설정과 성능

설정 파일: `Assets/Resources/Progression/DailyIncome.json`.

- 회사 수익 250,000원, 가용 현금 지출 상한 2%.
- 평가자산 기반 지불 의향 계수 0.0015, 최근 순성과 반영 계수 0.25.
- 배신감 감쇠 0.85, 공포 감쇠 0.5, 호기심 기본 가치 1,000원.
- 미사용 이용료 감정 반영 계수 4, 하루 최대 영향 4.

전 봇의 요금 판단은 장 전환 시 기존 배치 수만큼 나눠 처리한다. 마감 감정 처리는 24명마다 프레임을 양보한다. 화면은 열린 동안에만 0.5초 간격으로 값 변경을 확인한다. 정산 내역은 최근 32장, 회원별 가격 판단용 순성과는 최근 등록된 2,000명의 기록으로 제한한다. 봇의 기존 사건 기억과 실제 투자 이력은 삭제하지 않는다.

## 저장 범위와 제한

기존 프로젝트에는 전체 시장·계좌·봇 월드를 디스크에 저장하고 재시작 복구하는 기능이 없다. 현재의 `PlayerProgression.Capture/Restore`는 **같은 월드의 진행 상태 조각**이다. 이번에 회사 이름·당일 이용권·예수금·다음 요금·정산 이력을 그 형식에 추가했다. 오래된 정산 상태를 덮어써 재입금하거나 다른 월드에 가져오는 복구는 거부한다. 저장 조각 복구 자체는 현금을 움직이지 않는다.

따라서 종료 후 전체 게임 이어하기까지 구현했다고 볼 수 없다. 다음 우선순위는 전체 월드의 원자적 저장/복구와 장기간의 자연 발생 회원 모집·가격 균형 검증이다. 아래 통합 검증은 재현 가능한 계좌·명령 준비 조건을 사용한 기능 검증이며, 장기간 자연 시장에서 회원이 자동으로 몇 명 모이는지 입증하는 검증은 아니다.

## 검증

- 순수 원장 자동 검증 **250회 통과** (`Validation/DailyIncome/Core/results.txt`). 이 중 200회는 연속 장 마감 반복 검사다. 수수료·예약금·중복 청구·중복 정산·손익 공제·저장 조각·회원 교체 시 기록 상한을 확인했다.
- 구성한 1,000명의 다양한 자산·성향 집단에서 1천 원 수용 995명, 1만 원 수용 369명, 10만 원 수용 0명이었다. 자연 발생 가입 수의 예측값이 아닌 가격 수용 함수의 경향 검증이다.
- 기존 모집·위험 회귀 **27항목**, 뉴스 회귀 **36항목** 통과. 이 독립 채팅 테스트의 Unity 결제 어댑터는 비활성 경계 대역이며 실제 결제는 아래 Unity 통합 검사에서 검증했다.
- 실제 `TradeScene` 통합 검사 **58항목 통과**, 런타임 오류·예외 기록 없음. 실제 매칭으로 리딩방 해금 조건을 만든 뒤 초대, 유료 가입, 재입장, 예약금 보호, 과도한 가격 거절, 실제 조건부 매수·매도, 이용료 포함 손실 심리, 두 번의 시장 마감 및 다음 날 탈퇴까지 확인했다.
- 회사 이름 입력, 이용료 변경·닫기, 정산 열기·닫기는 실제 게임 카메라 좌표의 UI 레이캐스트를 거쳐 확인했다. 1600×900 및 1920×1080 촬영 결과를 직접 확인했고 새 패널의 TMP 잘림·누락 글리프도 검사했다.
- 첫 검증은 같은 프레임에 패널 열기와 적용을 연달아 시도해 클릭 검사가 실패했다. 실제 조작처럼 프레임 사이 간격을 두어 수정했다. 이후 화면에서 발견한 숫자 폰트의 한글 단위 누락은 숫자/단위 필드 분리로, 프로필 문구 겹침은 열린 패널의 그리기 순서로 해결하고 다시 촬영했다.
- 최종 실행 자원: **CPU 한 코어, BelowNormal, 20fps, timeScale 1, 84.1초, 최대 2,075 MiB**. 다른 Unity/게임/활성 검증이 있으면 시작하지 않는 가드를 사용했다. 장 전환 검사는 테스트 드라이버가 장의 경과 타이머를 끝으로 이동시켜 실제 정산 코루틴을 실행했다. 제품 배속 기능을 추가하지 않았으며 실제 시간 장기 관전 검증으로 표현하지 않는다.
- 임시 Unity 검증 드라이버는 실행 종료 후 `Validation/DailyIncome/capture-driver.cs.txt`로 보관하고 Assets에서 제거했다. 이후 런타임·에디터 C# 전체 컴파일 종료 코드 0. 배포용 플레이어 빌드는 만들지 않았다.
- 씬과 거래·계좌·실제 리딩방 주문 엔진의 작업 전 해시 일치 확인 완료.
