# 봇 채팅 사회화 시스템 구현 명세서 (Codex용)

Nov 15, 2026 · @최지수

## 0. 이 문서의 사용법

이 문서는 주식·코인 세력 시뮬레이션 게임의 봇 채팅을 "독립된 한 줄"에서 "서로 반응하는 대화"로 바꾸기 위한 구현 명세다. 작업자는 Codex(GPT-6 Astra, 추론 강도 max)를 전제로 한다.

작업 원칙은 다음과 같다.

1. **코드를 고치기 전에 2장의 조사를 먼저 끝낸다.** 조사 결과는 `docs/chat-social-audit.md`에 기록한다.
2. **기존 구조가 우선이다.** 이 문서의 필드명, 파일명, JSON 모양은 예시다. 기존 코드에 같은 역할의 구조가 있으면 그것을 확장하고, 새 이름을 중복으로 만들지 않는다.
3. **런타임에 LLM을 호출하지 않는다.** 모든 채팅은 규칙과 템플릿으로 생성한다. 같은 시드에서는 같은 결과가 나와야 한다.
4. **수치는 전부 출발값이다.** 문서의 모든 숫자는 12장의 설정 파일로 빼고, 코드에 직접 쓰지 않는다.
5. **채팅 문구는 한국어로 작성한다.** 주식 커뮤니티의 구어체를 쓰되, 실존 인물·기업·서비스 이름은 쓰지 않는다.
6. **모든 감정 변화에는 원인을 기록한다.** 어떤 메시지나 사건 때문에 값이 바뀌었는지 로그로 남긴다. 이 로그는 나중에 장마감 리포트의 재료가 된다.
7. **14장의 단계 순서대로 구현하고, 단계마다 완료 조건을 통과한 뒤 다음으로 넘어간다.**

다음 경우에는 구현을 멈추고 질문을 남긴다.

- 기존 세이브 데이터와 호환되지 않는 변경이 필요한 경우
- 이 문서의 규칙이 기존에 의도적으로 구현된 동작과 충돌하는 경우
- 게임 시간 체계(배속, 일시정지)가 이 문서의 가정과 다른 경우

### 용어

| 용어 | 뜻 |
| --- | --- |
| 봇 | AI 투자자 한 명 |
| 방 | 채팅 공간. 공용 채팅방 1개와 플레이어의 리딩방 여러 개 |
| 화행 | 메시지가 하는 일(자랑, 조롱, 질문 등). 문장 내용과 별개의 분류 |
| 스레드 | 서로 응답으로 이어진 메시지 묶음 |
| 목격자 | 메시지가 올라올 때 그 방에 있으면서 실제로 읽은 봇 |
| 게임 분 / 게임 시간 | 기존 게임 시간 체계의 단위. 배속과 일시정지를 그대로 따른다 |

## 1. 목표와 비목표

목표는 플레이어가 채팅창만 보고도 "누가 누구와 왜 이렇게 됐는지" 설명할 수 있는 대화를 만드는 것이다. 구현이 끝나면 아래 세 장면이 스크립트 없이 발생해야 한다.

**장면 A. 호출과 응답**

> 개미왕: @존버장인 노보 아직도 들고 계세요? ㅋㅋ 존버장인: @개미왕 네 들고 있습니다. 평단 620이라 아직 여유 있어요 개미왕: 여유는 무슨, 저번 달에도 그러다 반토막 났잖아요

**장면 B. 싸움에서 연쇄 퇴장까지**

1. 두 봇의 말다툼이 비꼼 → 언쟁 → 욕설로 올라간다.
2. 다른 봇이 "@방장 좀 말려주세요"라고 플레이어를 부른다.
3. 플레이어가 아무것도 하지 않으면 한쪽이 퇴장 인사를 남기고 방을 나간다.
4. 나간 봇과 친한 봇 한두 명이 "○○님 나가셨네요, 저도 갑니다"라며 따라 나간다.

**장면 C. 추방과 경각심**

1. 플레이어가 싸우던 두 봇을 추방한다.
2. 남은 봇들이 "싸우면 바로 퇴장이네요" 같은 반응을 보인다.
3. 한동안 그 방에서 싸움이 눈에 띄게 줄어든다.
4. 추방을 남발하면 방 전체의 말수가 줄어든다.

### 이번 범위에 포함

- 봇 간 관계 값과 기억
- 화행 기반 메시지 생성과 @호출 응답
- 분노 단계, 자진 퇴장, 동조 퇴장
- 플레이어 조치(경고, 채팅 금지, 추방)와 그 여파
- 신뢰·배신감 4분면 정리, FOMO의 상태 태그 전환
- 급관심종목 쏠림 수정

### 이번 범위에서 제외

- 런타임 LLM 호출
- 고래(세력·기관) 봇의 첩자 행위와 의도적 거짓말. 메시지에 `isLie` 필드만 예약해 둔다.
- 장마감 뉴스 패널과 사건 리포트 UI. 필요한 로그만 남긴다.
- 엔딩 조건, 자산 순위표
- 이동평균선, 매물대 등 차트 보조 지표

## 2. 구현 전 조사

아래 항목을 코드에서 확인하고 `docs/chat-social-audit.md`에 답을 적는다. 항목마다 근거가 되는 파일 경로와 함수명을 함께 적는다.

| 번호 | 확인할 것 | 왜 필요한가 |
| --- | --- | --- |
| Q1 | 채팅 문구를 생성하는 코드 위치와 현재 JSON 구조, 가중치가 적용되는 방식 | 4장의 파이프라인을 기존 구조 위에 얹을지 교체할지 결정 |
| Q2 | 현재 봇이 다른 봇을 호출하는 방식. 호출 대상이 데이터로 저장되는지, 문자열에만 있는지 | 5장의 응답 의무는 대상 ID가 데이터로 있어야 함 |
| Q3 | 탐욕, 공포, 신뢰도, 배신감, FOMO가 저장되는 위치와 각 값을 읽는 모든 지점 | FOMO 제거 시 영향 범위 파악 |
| Q4 | 리딩 명령 수락 판정식. 특히 `신뢰도 − 배신감` 형태로 합쳐서 쓰는지 | 합쳐 쓰고 있다면 9장의 4분면이 성립하지 않음 |
| Q5 | 봇과 봇 사이의 관계 값이 이미 있는지 | 3장의 관계 테이블을 새로 만들지 확장할지 결정 |
| Q6 | 봇의 고정 성향(투자 성향 등)이 어떤 필드로 있는지 | 3장의 성격 필드와 중복 방지 |
| Q7 | 리딩방 입장·퇴장·추방 기능의 현재 구현 상태와 UI | 7장, 8장의 연결 지점 |
| Q8 | 봇의 "채팅 목격 여부"가 현재 어떻게 결정되는지 | 목격자 효과의 기준 |
| Q9 | 게임 시간 체계: 단위, 배속, 일시정지, 장 시작과 마감 | 모든 감쇠와 지연 시간의 기준 |
| Q10 | 난수 생성 방식과 시드 고정 가능 여부 | 13장의 재현 가능한 테스트 |
| Q11 | 급관심종목 산정식과 봇이 매매할 종목을 고르는 로직 | 11장의 쏠림 원인 진단 |
| Q12 | 세이브 파일 형식과 버전 관리 방식 | 새 필드 추가 시 마이그레이션 |
| Q13 | 봇의 실제 매매 기록(언제 무엇을 얼마에 사고팔았는지)을 조회할 수 있는지 | 10장의 언행일치 규칙 |

조사 보고서 끝에는 다음 두 가지를 정리한다.

- **대응표:** 이 문서의 각 개념(성격, 관계, 기억, 메시지, 스레드, 방 상태)이 기존 코드의 어느 구조에 대응하는지, 없어서 새로 만드는지
- **충돌 목록:** 이 문서의 규칙과 다르게 동작하는 기존 로직과, 어느 쪽을 따를지에 대한 제안

## 3. 데이터 모델

봇의 상태를 "변하지 않는 성격", "시간에 따라 변하는 감정", "상대별 관계", "기억" 네 층으로 나눈다. 모든 수치는 따로 적지 않는 한 0\~100 정수다.

### 3.1 성격 (세션 시작 시 생성, 이후 고정)

| 필드 | 이름 | 높을 때의 행동 | 생성 분포 |
| --- | --- | --- | --- |
| `temper` | 다혈질 | 분노가 빨리 오른다 | 평균 50, 표준편차 20 |
| `grudge` | 뒤끝 | 분노와 배신감이 느리게 줄어든다 | 평균 45, 표준편차 25 |
| `suggestibility` | 귀 얇음 | 남의 채팅에 감정이 크게 움직인다 | 평균 50, 표준편차 20 |
| `sociability` | 수다 | 말을 자주 하고 호출에 잘 응답한다 | 평균 50, 표준편차 25 |
| `bravado` | 허세 | 자랑과 조롱을 자주 한다 | 평균 40, 표준편차 25 |
| `politeness` | 격식 | 존댓말을 유지한다. 낮으면 반말과 거친 표현 | 평균 60, 표준편차 25 |

- 분포는 정규분포로 뽑고 0\~100으로 자른다.
- `grudge`는 플레이어가 세션을 이어갈지 판단하는 "운" 요소다. 편차를 일부러 크게 둔다.
- 기존 투자 성향 필드가 있으면 유지하고, 위 여섯 필드만 추가한다.

### 3.2 감정 (변동)

| 필드 | 대상 | 비고 |
| --- | --- | --- |
| `greed` 탐욕 | 없음(전역) | 기존 유지. 초기값 50\~80 |
| `fear` 공포 | 없음(전역) | 기존 유지. 초기값 0 |
| `trust` 신뢰도 | 플레이어 | 기존 유지. 초기값 0 |
| `betrayal` 배신감 | 플레이어 | 기존 유지. 초기값 0 |
| `fomoUntil` | 없음(전역) | FOMO 상태가 끝나는 게임 시각. 없으면 null. 기존 FOMO 수치를 대체(10장) |

### 3.3 봇 간 관계 (신규)

방향이 있는 희소 테이블이다. A가 B를 어떻게 생각하는지와 B가 A를 어떻게 생각하는지는 별개의 행이다. 두 봇이 처음 상호작용할 때 행을 만든다.

```json
{
  "from": "bot_017",
  "to": "bot_042",
  "affinity": 0,
  "anger": 0,
  "lastInteractionAt": 123456
}
```

| 필드 | 범위 | 뜻 |
| --- | --- | --- |
| `affinity` 호감 | −100\~100, 초기값 0 | 편들기, 위로, 동조 퇴장의 기준 |
| `anger` 분노 | 0\~100, 초기값 0 | 특정 상대를 향한 분노. 전역 수치가 아니다 |

- 세션 시작 시 봇마다 무작위 상대 2\~4명과 `affinity` 30\~70의 행을 미리 만든다. 처음부터 친한 무리가 있어야 동조 퇴장과 편들기가 초반부터 발생한다.
- 플레이어에게 보여주는 봇의 "분노" 수치는 그 봇의 모든 행 중 `anger` 최댓값이다. 누구를 향한 것인지 함께 표시한다.

### 3.4 기억 (신규)

봇마다 최대 8개를 보관한다. 가득 차면 `salience`가 가장 낮고 오래된 것부터 버린다.

```json
{
  "type": "LOSS_BY_LEAD",
  "actorId": "player",
  "targetId": "bot_017",
  "symbol": "노보",
  "amount": -20000000,
  "pct": -31.5,
  "at": 120000,
  "salience": 90,
  "usedCount": 0
}
```

| `type` | 생성 조건 | `salience` |
| --- | --- | --- |
| `LOSS_BY_LEAD` | 플레이어 리딩을 따랐다가 자산의 10% 이상 손실 | 90 |
| `GAIN_BY_LEAD` | 플레이어 리딩을 따라 자산의 10% 이상 수익 | 70 |
| `KICKED` | 자신이 추방당함 | 85 |
| `FOUGHT` | 특정 봇과 분노 2단계 이상의 싸움 | 60 |
| `SAW_KICK` | 다른 봇의 추방을 목격 | 45 |
| `SAW_BRAG_THEN_CRASH` | 자랑한 봇이 그 종목에서 큰 손실을 봄 | 40 |
| `BIG_SELF_LOSS` / `BIG_SELF_GAIN` | 리딩과 무관한 자산 15% 이상 손익 | 50 |

### 3.5 메시지

화면에 보이는 문자열과 별도로, 아래 구조를 데이터로 저장한다. 응답과 감정 효과는 문자열이 아니라 이 데이터를 기준으로 처리한다.

```json
{
  "id": "msg_8841",
  "roomId": "lead_1",
  "senderId": "bot_017",
  "at": 123456,
  "act": "MOCK",
  "targetId": "bot_042",
  "replyToId": "msg_8839",
  "threadId": "th_112",
  "topic": { "symbol": "노보", "event": "PRICE_DROP" },
  "facts": { "pct": -12.4 },
  "templateKey": "MOCK.casual.2.memory.03",
  "text": "@존버장인 저번 달에도 그러다 반토막 났잖아요",
  "isLie": false,
  "debug": { "trigger": "REPLY_OBLIGATION", "weights": {} }
}
```

### 3.6 스레드

```json
{
  "id": "th_112",
  "roomId": "lead_1",
  "kind": "ARGUMENT",
  "participants": ["bot_017", "bot_042"],
  "turnCount": 3,
  "maxTurns": 6,
  "status": "ACTIVE",
  "endReason": null
}
```

`kind`는 `CHAT`(잡담), `QUESTION`(질문과 답), `ARGUMENT`(언쟁) 셋 중 하나다.

### 3.7 방 상태 (리딩방마다)

| 필드 | 초기값 | 뜻 |
| --- | --- | --- |
| `discipline` 경각심 | 0 | 높을수록 싸움이 덜 발생한다. 플레이어의 제재로 오른다 |
| `chill` 위축 | 0 | 높을수록 모두의 말수가 줄어든다. 부당하거나 잦은 추방으로 오른다 |

두 값은 리딩방 상단에 작은 수치로 표시한다. 플레이어가 자기 조치의 결과를 바로 볼 수 있어야 한다.

## 4. 메시지 생성 파이프라인

메시지 하나는 동기 → 화행 → 사실 → 말투의 네 단계를 순서대로 거쳐 만들어진다. 문장을 통째로 고르는 방식은 쓰지 않는다.

### 4.1 1단계: 동기 (왜 지금 말하는가)

사건이 발생하면 해당 봇에게 "발화 의도"를 큐에 넣는다. 봇은 자기 차례에 우선순위가 가장 높은 의도 하나만 처리하고, 유효 시간이 지난 의도는 버린다.

| 우선순위 | 동기 | 발생 조건 | 유효 시간 |
| --- | --- | --- | --- |
| 1 | `REPLY_OBLIGATION` | 누군가 자신을 @호출함 (5장) | 20초 |
| 2 | `EMOTION_THRESHOLD` | 분노 단계가 올랐거나, 공포·탐욕이 80을 넘음 | 30초 |
| 3 | `SELF_EVENT` | 자기 매매 체결, 큰 손익, 리딩 결과 확정 | 60초 |
| 4 | `WITNESSED_EVENT` | 보유·관심 종목의 급등락, 다른 봇의 메시지, 제재 목격 | 45초 |
| 5 | `IDLE` | 일정 시간 아무 말도 안 함 | 없음 |

유효 시간은 1배속 기준 실제 초다. 배속에 비례해 줄어든다.

발화량 제한은 다음과 같다.

- 봇 한 명은 메시지를 보낸 뒤 `speakCooldownSec`(기본 6초) 동안 다시 말하지 않는다. 응답 의무는 이 제한을 절반으로 줄인다.
- 방 하나에는 10초에 최대 `roomMaxMsgPer10Sec`(기본 5)개까지만 올라온다. 넘치면 우선순위가 낮은 의도부터 버린다.
- `IDLE` 발화 확률은 `sociability`에 비례하고, 방의 `chill`에 반비례한다.

### 4.2 2단계: 화행 (무엇을 하는 말인가)

| 화행 | 이름 | 대상 | 주로 나오는 상황 |
| --- | --- | --- | --- |
| `BRAG` | 자랑 | 없음 또는 봇 | 수익 확정, 허세 높음 |
| `LAMENT` | 한탄 | 없음 | 손실, 공포 높음 |
| `ASK` | 질문 | 봇 또는 방 전체 | 급등락 목격, 판단 망설임 |
| `ANSWER` | 답변 | 봇 | 질문에 대한 응답 |
| `AGREE` | 동조 | 봇 | 호감 높은 상대의 말, 같은 종목 보유 |
| `REBUT` | 반박 | 봇 | 반대 포지션, 의견 충돌 |
| `DOUBT` | 의심 | 봇 또는 플레이어 | 자랑이나 리딩에 대한 불신 |
| `MOCK` | 조롱 | 봇 | 분노 1단계 이상, 상대의 손실 |
| `INSULT` | 욕설 | 봇 | 분노 3단계 이상에서만 가능 |
| `COMFORT` | 위로 | 봇 | 호감 높은 상대의 한탄 |
| `APOLOGIZE` | 사과 | 봇 | 언쟁 중 분노가 식었거나 경고를 받음 |
| `MEDIATE` | 중재 | 싸우는 두 봇 | 제3자, 수다 높고 다혈질 낮음 |
| `PRAISE_PLAYER` | 방장 칭찬 | 플레이어 | 리딩 수익 |
| `WARN_PLAYER` | 방장 경고 | 플레이어(다른 봇에게 알림) | 리딩 손실, 추방당함 |
| `CALL_PLAYER` | 방장 호출 | 플레이어 | 싸움이 3단계에 도달했는데 조치가 없음 |
| `REACT` | 반응 | 없음 | 제재, 퇴장, 큰 사건을 목격 |
| `SMALLTALK` | 잡담 | 없음 또는 봇 | `IDLE` |
| `FAREWELL` | 퇴장 인사 | 없음 또는 봇 | 방을 나가기 직전 |

화행은 가중치 추첨으로 고른다.

```
최종 가중치 = 기본 가중치[동기][화행]
            × 성격 보정 × 감정 보정 × 관계 보정 × 방 보정
```

- **기본 가중치:** 동기별로 가능한 화행과 그 가중치를 설정 파일에 표로 둔다.
- **성격 보정:** 예) `BRAG`, `MOCK`은 `0.5 + bravado/100`배. `MEDIATE`는 `(sociability/100) × (1.5 − temper/100)`배.
- **감정 보정:** 예) `LAMENT`는 `0.5 + fear/100`배. `MOCK`, `REBUT`, `INSULT`는 대상을 향한 분노 단계에 따라 7장의 배율을 곱한다.
- **관계 보정:** 예) `AGREE`, `COMFORT`는 대상에 대한 `affinity`가 높을수록, `MOCK`, `DOUBT`는 낮을수록 커진다.
- **방 보정:** `MOCK`, `INSULT`, `REBUT`은 `1 − discipline/150`배.

가중치 합이 0이면 말하지 않는다. 선택 과정의 가중치는 메시지의 `debug.weights`에 저장한다.

### 4.3 3단계: 사실 (무엇에 대해 말하는가)

템플릿의 빈칸은 시뮬레이션의 실제 값으로만 채운다.

| 슬롯 | 출처 |
| --- | --- |
| `{target}` | 대상 봇의 닉네임 |
| `{symbol}` | 화자가 보유했거나 방금 거래한 종목, 또는 스레드의 주제 종목 |
| `{pct}` | 화자의 그 종목 실제 수익률, 또는 종목의 실제 등락률 |
| `{amount}` | 실제 손익 금액. 구어체 단위로 반올림 ("2천", "350만 원") |
| `{avgPrice}` | 화자의 실제 평균 매수가 |
| `{price}` | 현재가 또는 리딩의 목표가 |
| `{memSymbol}`, `{memPct}`, `{memWhen}` | 기억(3.4)에서 가져온 과거 사건 |

- 필요한 슬롯을 채울 수 없는 템플릿은 후보에서 뺀다. 값을 지어내지 않는다.
- 후보가 하나도 없으면 2단계로 돌아가 다음 순위 화행을 고른다.

### 4.4 4단계: 말투 (어떻게 말하는가)

템플릿은 화행, 격식, 강도, 변형의 네 축으로 분류한다.

| 축 | 값 | 결정 기준 |
| --- | --- | --- |
| 격식 | `formal`(존댓말), `casual`(반존대·구어), `rough`(반말) | `politeness` 67 이상 / 34\~66 / 33 이하. 분노 3단계 이상이면 한 단계 내려간다 |
| 강도 | 1, 2, 3 | 화행과 관련된 감정 값이 0\~39 / 40\~69 / 70 이상 |
| 변형 | `plain`, `memory` | 대상에 대한 기억이 있으면 `memoryMentionChance`(기본 0.4) 확률로 `memory` |

템플릿 파일 예시:

```json
{
  "MOCK": {
    "casual": {
      "2": {
        "plain": [
          "@{target} {symbol} 아직도 들고 계세요? ㅋㅋ",
          "@{target} 그 가격에 사신 분이 훈수를 두시네"
        ],
        "memory": [
          "@{target} {memWhen} {memSymbol}에서도 그러다 {memPct}% 날리셨잖아요"
        ]
      }
    }
  }
}
```

템플릿 분량 기준은 다음과 같다.

- 화행 × 격식 × 강도 조합마다 `plain` 최소 6개
- 대상이 있는 공격·의심 계열(`MOCK`, `REBUT`, `DOUBT`, `WARN_PLAYER`)은 `memory` 최소 4개
- 템플릿 선택 후 후처리로 어미 장식을 확률적으로 붙인다: 탐욕이 높으면 "ㅋㅋ", "가즈아", 공포가 높으면 "ㅠㅠ", "...", 분노가 높으면 "?", "아니". 장식 목록도 설정 파일에 둔다.

표현 수위 규칙: `INSULT`는 "어이없네", "정신 차려라", "입만 살았네" 수준의 거친 말로 제한한다. 비속어, 혐오 표현, 특정 집단 비하는 쓰지 않는다.

## 5. 대화 스레드와 @호출

`targetId`가 있는 메시지는 대상에게 응답 의무를 만들고, 응답이 이어지면 스레드가 된다. 현재의 "호출은 하지만 상호작용이 없다"는 문제를 해결하는 장이다.

### 5.1 호출 규칙

- 대상이 봇인 메시지는 항상 `@닉네임`으로 시작한다. 화면의 `@닉네임`과 데이터의 `targetId`는 항상 일치해야 한다.
- 호출 대상은 그 방에 현재 있는 봇만 가능하다. 퇴장했거나 채팅 금지 중인 봇은 호출 대상에서 제외한다.
- 새 대화를 거는 호출의 대상은 다음 순서로 고른다: 방금 말한 봇 → 같은 종목을 보유한 봇 → `affinity`나 `anger`의 절댓값이 큰 봇.
- 플레이어를 부를 때는 `@방장`으로 표기한다.

### 5.2 응답 의무

호출받은 봇은 아래 확률로 `REPLY_OBLIGATION` 의도를 얻는다.

```
응답 확률 = 화행별 기본 확률
          + (sociability − 50) × 0.004
          + (발신자를 향한 anger) × 0.003
          − (방의 chill) × 0.003
(0.05~0.98로 자른다)
```

| 받은 화행 | 기본 응답 확률 |
| --- | --- |
| `INSULT` | 0.90 |
| `REBUT` | 0.80 |
| `MOCK` | 0.75 |
| `ASK` | 0.70 |
| `DOUBT` | 0.70 |
| `APOLOGIZE` | 0.65 |
| `COMFORT`, `AGREE` | 0.50 |
| `BRAG`(대상 지정) | 0.50 |
| `ANSWER`, `MEDIATE` | 0.40 |
| `SMALLTALK` | 0.35 |

- 응답은 `replyDelaySec`(기본 2\~7초 사이 무작위) 뒤에 올라온다. 즉시 응답하면 기계처럼 보인다.
- 응답하지 않기로 결정되면 "무시"로 기록한다. 무시당한 발신자는 6장의 무시 효과를 받는다.

### 5.3 응답 화행 표

응답할 화행은 받은 화행에 따라 아래 후보에서 고른다. 숫자는 기본 가중치이고, 4.2의 보정을 그대로 적용한다.

| 받은 화행 | 응답 후보 (기본 가중치) |
| --- | --- |
| `MOCK` | `MOCK` 35, `REBUT` 30, `DOUBT` 10, `SMALLTALK`(웃어넘김) 15, `LAMENT`(위축) 10 |
| `INSULT` | `INSULT` 40(3단계 이상일 때만), `MOCK` 30, `REBUT` 20, `CALL_PLAYER` 10 |
| `REBUT` | `REBUT` 45, `MOCK` 20, `AGREE`(수긍) 15, `ASK` 10, `APOLOGIZE` 10 |
| `DOUBT` | `ANSWER`(근거 제시) 45, `REBUT` 30, `MOCK` 15, `BRAG` 10 |
| `ASK` | `ANSWER` 80, `ASK`(되묻기) 10, `SMALLTALK` 10 |
| `BRAG` | `AGREE`(축하) 35, `DOUBT` 25, `MOCK`(시기) 15, `ASK`(비결 질문) 25 |
| `LAMENT` | `COMFORT` 50, `MOCK` 20, `AGREE`(같이 한탄) 30 |
| `COMFORT`, `AGREE` | `AGREE` 60, `SMALLTALK` 40 |
| `APOLOGIZE` | `AGREE`(받아줌) 60, `MOCK`(안 받아줌) 25, `APOLOGIZE`(맞사과) 15 |
| `MEDIATE` | `AGREE`(수긍) 50, `REBUT`("넌 빠져") 30, 무응답 20 |

추가 제약:

- `ANSWER`와 `BRAG`는 답할 사실이 있을 때만 선택할 수 있다. 예를 들어 "아직 들고 있냐"는 질문에는 실제 보유 여부로 답한다.
- `AGREE`(수긍)와 `APOLOGIZE`의 가중치는 `1.5 − temper/100`배다. 다혈질일수록 물러서지 않는다.

### 5.4 스레드 생성과 분류

- 첫 응답이 올라오는 순간 스레드를 만들고, 원 메시지와 응답에 같은 `threadId`를 붙인다.
- 스레드 안에 `MOCK`, `REBUT`, `INSULT`가 합쳐 2회 이상 나오면 `kind`를 `ARGUMENT`로 바꾼다.
- `maxTurns`는 생성 시 `CHAT` 2\~4, `QUESTION` 2\~3 중에서 뽑는다. `ARGUMENT`로 바뀌면 4\~8로 다시 뽑는다.
- 봇 한 명은 동시에 활성 스레드 하나에만 참여한다.
- 방 하나의 활성 스레드는 최대 2개, 그중 `ARGUMENT`는 최대 1개다. 플레이어가 따라 읽을 수 있어야 한다.

### 5.5 제3자 참여

스레드 메시지를 목격한 봇은 아래 조건에서 끼어든다. 참여자는 스레드당 최대 4명이다.

| 참여 방식 | 조건 | 화행 |
| --- | --- | --- |
| 편들기 | 한쪽 참여자에 대한 `affinity` 40 이상 | 친구에게 `AGREE`, 또는 상대에게 `REBUT` |
| 중재 | `ARGUMENT`이고, `sociability` 60 이상, `temper` 50 이하 | `MEDIATE` |
| 방장 호출 | `ARGUMENT`가 분노 3단계에 도달했고 플레이어 조치가 없음 | `CALL_PLAYER` |
| 구경 | `bravado` 60 이상, 양쪽 모두에 `affinity` 20 미만 | `REACT`("팝콘 가져옵니다") |

메시지 하나당 제3자 참여 확률은 `thirdPartyJoinChance`(기본 0.15)에 `sociability/50`을 곱한 값이다.

### 5.6 종료 조건

아래 중 하나가 충족되면 스레드를 닫고 `endReason`을 기록한다.

| `endReason` | 조건 |
| --- | --- |
| `MAX_TURNS` | `turnCount`가 `maxTurns`에 도달 |
| `NO_REPLY` | 응답 의무가 무시로 끝남 |
| `RESOLVED` | `APOLOGIZE`가 받아들여지거나 `MEDIATE`가 성공 |
| `EXIT` | 참여자가 방을 나감 (7장) |
| `PLAYER_ACTION` | 플레이어가 참여자를 경고·채팅 금지·추방함 (8장) |
| `INTERRUPTED` | 참여자의 보유 종목이 `interruptPricePct`(기본 5%) 이상 급변함. 참여자는 그 종목 이야기로 넘어간다 |

닫힌 스레드의 참여자끼리는 `threadCooldownSec`(기본 60초) 동안 새 스레드를 만들지 않는다. 단, 분노는 남아 있으므로 다음 충돌은 더 높은 단계에서 시작된다.

## 6. 화행별 감정 효과

메시지가 올라오면 수신자와 목격자의 감정이 아래 표대로 바뀐다. 모든 변화는 원인 메시지 ID와 함께 로그에 남긴다.

### 6.1 수신자 효과 (호출당한 봇)

"발신자를 향한"은 3.3 관계 테이블의 수신자→발신자 행을 뜻한다.

| 받은 화행 | 발신자를 향한 `anger` | 발신자를 향한 `affinity` | 그 밖의 효과 |
| --- | --- | --- | --- |
| `DOUBT` | +4 | −2 |  |
| `REBUT` | +6 | −3 |  |
| `MOCK` | +12 | −8 | 손실 중이면 `fear` +3 |
| `INSULT` | +25 | −20 |  |
| `AGREE` | −3 | +5 |  |
| `COMFORT` | −5 | +8 | `fear` −4 |
| `APOLOGIZE` | −20 | +5 |  |
| `ANSWER` | 0 | +2 |  |
| `MEDIATE` 성공 | 싸우던 상대를 향한 `anger` −12 | 중재자에게 +3 |  |
| `MEDIATE` 실패 | 중재자를 향한 `anger` +5 | 중재자에게 −3 |  |
| 무시당함(응답 없음) | +3 | −2 | 호출했던 쪽에 적용 |

보정 규칙:

- `anger` 증가량에는 `(0.5 + temper/100) × (1 − discipline/200)`을 곱한다.
- 메시지 하나로 오르는 `anger`는 최대 `angerMaxGainPerMsg`(기본 25)다.
- 메시지 하나로 분노 단계(7장)는 최대 한 단계만 오른다. 넘치는 분량은 다음 단계 경계 바로 아래에서 자른다.
- `MEDIATE` 성공 확률은 `0.3 + (싸우는 두 봇이 중재자에게 가진 affinity의 평균)/200`이다. 두 봇 중 하나라도 분노 3단계 이상이면 절반으로 줄인다.

### 6.2 목격자 효과 (그 방에서 메시지를 읽은 다른 봇)

| 목격한 화행 | 목격자의 조건 | 효과 |
| --- | --- | --- |
| `MOCK`, `INSULT` | 피해자에 대한 `affinity` 40 이상 | 가해자를 향한 `anger` +4(`MOCK`), +8(`INSULT`) |
| `INSULT` | 모든 목격자 | 가해자를 향한 `affinity` −4 |
| `BRAG` | 최근 수익률이 자랑한 봇보다 낮음 | `greed` +4, FOMO 판정(10장) |
| `BRAG` | 손실 중 | 자랑한 봇을 향한 `affinity` −3 |
| `LAMENT` | 같은 종목 보유 | `fear` +6 |
| `LAMENT` | 같은 종목 미보유 | `fear` +2 |
| `PRAISE_PLAYER` | 모든 목격자 | 플레이어 `trust` +3 |
| `WARN_PLAYER` | 모든 목격자 | 플레이어 `trust` −4 |
| `FAREWELL` | 나가는 봇에 대한 `affinity` 60 이상 | 동조 퇴장 판정(7.4) |

보정 규칙:

- 목격자 효과에는 `0.5 + suggestibility/100`을 곱한다.
- 목격 여부는 기존 목격 판정 로직(조사 Q8)을 그대로 쓴다. 없으면 `witnessChance`(기본 0.6)에 `sociability` 보정을 곱해 메시지마다 판정한다.
- **스레드 하나가 목격자 한 명에게 주는 감정 변화는 항목당 합계 ±10을 넘지 않는다.** 같은 싸움을 오래 봤다고 감정이 무한히 쌓이지 않게 하는 장치다.
- **같은 사건에 대한 `PRAISE_PLAYER`와 `WARN_PLAYER`는 목격자 한 명에게 사건당 한 번만 적용한다.** 사건은 리딩 한 건 단위로 식별한다.

### 6.3 직접 경험과 간접 경험의 구분

- **배신감은 직접 경험으로만 오른다.** 리딩을 따랐다가 본 손실, 자신이 당한 추방·채팅 금지가 직접 경험이다.
- **채팅 목격 같은 간접 경험은 신뢰도만 움직인다.** 남의 경고를 들은 봇은 플레이어를 덜 믿게 될 뿐, 배신감을 느끼지는 않는다.
- 간접 경험으로 움직이는 신뢰도는 봇 한 명당 게임 하루에 ±`indirectTrustDailyCap`(기본 15)까지다.

기존 구현이 채팅 목격으로 배신감을 올리고 있다면 조사 보고서의 충돌 목록에 적는다. 이 문서의 규칙을 기본으로 따른다.

### 6.4 시간 감쇠

| 값 | 게임 1시간당 감소량 |
| --- | --- |
| `anger` | `angerDecayPerHour`(기본 6) × `(1.5 − grudge/100)` |
| `betrayal` | 기존 감쇠량 × `(1.5 − grudge/100)` |
| `affinity` | 감쇠 없음 |
| `discipline` | `disciplineDecayPerHour`(기본 3) |
| `chill` | `chillDecayPerHour`(기본 4) |

`grudge`가 100인 봇은 분노와 배신감이 평균의 절반 속도로 줄고, 0인 봇은 1.5배 속도로 준다.

## 7. 분노 단계와 퇴장

퇴장은 반드시 네 단계를 차례로 거쳐 일어난다. 플레이어가 싸움을 알아차리고 개입할 시간을 보장하기 위해서다.

### 7.1 단계 정의

단계는 특정 상대를 향한 `anger` 값으로 결정한다.

| 단계 | `anger` | 이름 | 그 상대에 대한 행동 변화 | 화면 표시 |
| --- | --- | --- | --- | --- |
| 0 | 0\~29 | 평온 | 없음 | 없음 |
| 1 | 30\~54 | 비꼼 | `MOCK`, `DOUBT` 가중치 2배 | 없음 |
| 2 | 55\~74 | 언쟁 | `REBUT`, `MOCK` 가중치 3배. 상대가 말하면 호출 없이도 끼어든다 | 닉네임 옆 작은 주황 점 |
| 3 | 75\~89 | 욕설 | `INSULT` 가능. 격식이 한 단계 내려간다. `AGREE`, `APOLOGIZE` 가중치 0.3배 | 닉네임 옆 작은 빨간 점 |
| 4 | 90\~100 | 퇴장 예고 | 퇴장 유예 시간 시작 (7.2) | 빨간 점 깜빡임 |

- 단계가 오를 때마다 `EMOTION_THRESHOLD` 동기를 만들어, 단계에 맞는 메시지가 한 번은 올라오게 한다. 플레이어는 단계 상승을 채팅으로 볼 수 있어야 한다.
- 2단계에 처음 도달하면 양쪽에 `FOUGHT` 기억을 만든다.
- 3단계에 도달한 뒤 `callPlayerDelaySec`(기본 8초) 안에 플레이어 조치가 없으면, 목격자 중 한 명이 `CALL_PLAYER`("@방장 좀 말려주세요")를 올린다. 싸움 한 건당 한 번만 올린다.

### 7.2 자진 퇴장

1. 한 봇이 4단계에 도달하면 `exitGraceSec`(기본 15초, 1배속 실제 초)의 유예 시간이 시작된다.
2. 유예 시작과 함께 예고 메시지를 올린다. 예) "이런 방에 더 있을 이유가 없네요"
3. 유예 시간 동안 플레이어 조치, 상대의 `APOLOGIZE`, `MEDIATE` 성공이 있으면 6장·8장의 규칙대로 `anger`가 내려간다.
4. 유예 시간이 끝났을 때 `anger`가 `exitConfirmThreshold`(기본 85) 이상이면 `FAREWELL`을 올리고 방을 나간다. 미만이면 3단계로 돌아간다.
5. 싸우던 두 봇이 모두 4단계면 먼저 도달한 쪽만 나간다. 남은 쪽의 `anger`는 상대가 사라졌으므로 30 낮춘다.

나간 봇에게 일어나는 일:

- 리딩방에서만 나간다. 시장과 공용 채팅방에는 그대로 남는다.
- 플레이어 `trust` −10. 방을 관리하지 않았다는 불만이다.
- `grudge/100 × 0.6`의 확률로, 게임 1시간 안에 공용 채팅방에 `WARN_PLAYER`("그 방 분위기 엉망입니다")를 올린다.
- `rejoinCooldownHours`(기본 게임 24시간) 동안 그 방의 초대를 거절한다. 이후에는 `trust`에 따라 초대를 받을 수 있다.

### 7.3 방치된 싸움의 대가

싸움이 3단계에 도달했는데 플레이어가 끝까지 조치하지 않으면, 그 싸움을 목격한 봇 전원의 플레이어 `trust`가 2 내려간다. 싸움 한 건당 한 번만 적용한다.

### 7.4 동조 퇴장

봇이 자진 퇴장하거나 추방당하면, 남은 봇 중 나간 봇에 대한 `affinity`가 `sympathyExitMinAffinity`(기본 60) 이상인 봇만 판정한다.

```
동조 퇴장 확률 = (affinity − 50) / 100
               × (1 − 플레이어 trust / 150)
               × (1 − discipline / 200)
```

- 판정은 봇마다 한 번만 한다.
- 나가기로 결정된 봇은 5\~25초 사이의 서로 다른 지연 뒤에 나간다. 한꺼번에 빠지지 않는다.
- 나갈 때 반드시 원인을 밝히는 `FAREWELL`을 올린다. 예) "@개미왕 님 나가셨네요. 저도 이만 가보겠습니다"
- **동조 퇴장은 연쇄되지 않는다.** 동조 퇴장한 봇을 보고 또 나가는 판정은 하지 않는다(`sympathyExitDepth` 기본 1).
- 퇴장 한 건이 유발하는 동조 퇴장은 방 인원의 `sympathyExitMaxRatio`(기본 25%)까지다. 넘치면 `affinity`가 높은 순으로 자른다.
- 동조 퇴장한 봇은 플레이어 `trust` −5를 받고, 7.2의 재입장 제한을 절반 기간으로 받는다.

남은 봇은 퇴장을 목격하고 `REACT`를 올릴 수 있다. 예) "방이 왜 이래요", "조용해져서 좋네요"

## 8. 플레이어 조치

플레이어는 자기 리딩방의 봇에게 경고, 채팅 금지, 추방 세 가지 조치를 할 수 있다. 봇의 닉네임을 누르면 나오는 작은 메뉴에 세 항목을 둔다. 조치는 "방장님이 ○○님을 내보냈습니다" 같은 시스템 메시지로 방에 표시한다.

### 8.1 조치별 효과

| 조치 | 대상 봇 | 방 상태 | 스레드 |
| --- | --- | --- | --- |
| 경고 | 싸우던 상대를 향한 `anger` −15. `temper` 70 이상이면 `trust` −3 | `discipline` +5 | 60% 확률로 종료. 대상이 `APOLOGIZE`할 수 있다 |
| 채팅 금지 | `muteMinutes`(기본 게임 30분) 동안 발화 불가. `trust` −5 | `discipline` +8 | 즉시 종료 |
| 추방 | 방에서 제거. 효과는 8.2 | 8.2 | 즉시 종료 |

- 같은 봇에게 게임 10분 안에 경고를 반복하면 `anger` 감소 효과가 매번 절반으로 준다.
- 채팅 금지 중에도 분노는 6.4의 속도로만 줄어든다. 금지가 풀렸을 때 `grudge` 70 이상이면 비꼬는 한마디를 올린다.
- 싸움 중에 한쪽만 경고하거나 채팅 금지하면, 그 봇은 "왜 저만"이라는 불만으로 `trust` −3을 추가로 받는다.

### 8.2 추방의 세 가지 경우

추방의 여파는 남은 봇들이 그 추방을 어떻게 받아들이느냐에 따라 다르다. 판정은 추방 시점의 대상 봇 상태로 한다.

| 경우 | 판정 조건 | `discipline` | `chill` | 남은 봇의 플레이어 `trust` |
| --- | --- | --- | --- | --- |
| 정당한 추방 | 대상이 분노 2단계 이상으로 싸우는 중이었음 | +20 | 0 | 일반 목격자 +2 |
| 안티 정리 | 대상의 `betrayal`이 60 이상이었음 | +5 | 0 | 일반 목격자 +1 |
| 임의 추방 | 위 두 조건에 해당하지 않음 | +5 | +8 | 변화 없음 |

세 경우 모두에 공통으로 적용하는 규칙:

- 추방당한 봇에 대한 `affinity`가 60 이상인 봇은 위 표의 신뢰 변화 대신 `trust` −5를 받고, 7.4의 동조 퇴장 판정을 받는다.
- 싸우던 두 봇을 `bothKickWindowSec`(기본 20초) 안에 모두 추방하면 `discipline`을 10 더 올린다. 한쪽만 추방하면 추방당한 봇의 친구들이 받는 `trust` 감소가 −5에서 −8로 커진다.
- 게임 1시간 안에 추방이 `kickSpamCount`(기본 3)회를 넘으면, 넘는 추방마다 `chill` +10을 추가한다.

추방당한 봇에게 일어나는 일:

- 플레이어 `trust` −30, `betrayal` +15. `KICKED` 기억을 만든다.
- `0.3 + grudge/200`의 확률로, 게임 1시간 안에 공용 채팅방에 `WARN_PLAYER`를 올린다.
- 그 방에는 다시 들어오지 않는다. 플레이어의 다른 리딩방 초대는 `trust`와 `betrayal`에 따라 판정한다.

### 8.3 경각심과 위축이 하는 일

| 방 상태 | 효과 | 플레이어가 알아차리는 방법 |
| --- | --- | --- |
| `discipline` | `anger` 증가량이 `1 − discipline/200`배. `MOCK`, `INSULT`, `REBUT` 가중치가 `1 − discipline/150`배 | 20 이상으로 오를 때 봇이 `REACT`를 올린다. 예) "싸우면 바로 퇴장이네요..." |
| `chill` | `IDLE` 발화 확률과 응답 확률이 줄어든다. `IDLE` 발화 확률은 `1 − chill/125`배, 최소 0.2배 | 30 이상으로 오를 때 봇이 `REACT`를 올린다. 예) "요즘 방 분위기 무섭네요" |

- 두 값 모두 0\~100으로 자른다.
- `chill`이 높은 방에서는 `PRAISE_PLAYER`도 줄어든다. 플레이어에게는 조용한 방이 공짜가 아니라는 뜻이다. 칭찬이 공용 채팅방으로 퍼지는 속도가 느려진다.

### 8.4 설계 의도

플레이어가 수치를 보고 마음에 안 드는 봇을 내보내는 행동은 허용되고, 효과적이어야 한다. 그래서 임의 추방의 불이익은 `chill` +8과 친구들의 반발뿐이다. 불이익이 커지는 것은 짧은 시간에 여러 명을 내보낼 때뿐이다.

## 9. 신뢰와 배신감의 4분면

신뢰도와 배신감은 합치거나 빼서 쓰지 않는다. 두 값의 조합으로 네 가지 상태를 정하고, 상태마다 행동이 다르다.

### 9.1 상태 정의

기준선은 두 값 모두 `quadrantThreshold`(기본 50)다.

| 상태 | 신뢰도 | 배신감 | 한 줄 요약 |
| --- | --- | --- | --- |
| 충성 `LOYAL` | 높음 | 낮음 | 믿고 따른다 |
| 애증 `AMBIVALENT` | 높음 | 높음 | 욕하면서 따른다 |
| 적대 `HOSTILE` | 낮음 | 높음 | 따르지 않고 경고하고 다닌다 |
| 무관심 `INDIFFERENT` | 낮음 | 낮음 | 관심이 없다 |

- 상태가 경계에서 깜빡이지 않도록 이력 폭을 둔다. 높음으로 바뀌려면 55 이상, 낮음으로 바뀌려면 45 이하여야 한다.
- 상태는 리딩방의 봇 목록에서 두 수치 옆에 태그로 표시한다.

### 9.2 상태별 행동

| 행동 | 충성 | 애증 | 적대 | 무관심 |
| --- | --- | --- | --- | --- |
| 리딩 수락 확률 | `0.50 + trust/200` | `0.35 + trust/300` | 0 | `trust/200` |
| 투입 금액 (성향 기본값 대비) | `0.6 + trust/250`배 | 0.5배 | 해당 없음 | 0.4배 |
| 목표가까지 보유 | 목표가까지 보유 | 목표 수익의 60\~80% 지점에서 먼저 매도 | 해당 없음 | 목표가까지 보유 |
| 손절 기준 | 성향 기본값 | 기본값의 절반 폭에서 손절 | 해당 없음 | 성향 기본값 |
| 수익 시 `trust` 증가 | 1.0배 | 0.5배 | 해당 없음 | 1.0배 |
| 수익 시 `betrayal` 감소 | 해당 없음 | 수익률에 비례해 감소 | 해당 없음 | 해당 없음 |
| 손실 시 `betrayal` 증가 | 1.0배 | 1.5배 | 해당 없음 | 1.0배 |
| 리딩방 안 채팅 | `PRAISE_PLAYER`, `AGREE` | 리딩을 따르면서 `DOUBT`, `MOCK`을 플레이어에게 | `WARN_PLAYER`, `DOUBT` | 플레이어 언급 없음 |
| 공용 채팅방 | 칭찬을 퍼뜨린다 | 칭찬도 경고도 하지 않는다 | 경고를 퍼뜨린다 | 언급 없음 |
| 리딩방 잔류 | 남는다 | 남는다 | 게임 1시간마다 `betrayal/200` 확률로 자진 퇴장 | 게임 하루마다 10% 확률로 조용히 퇴장 |

애증 상태의 대표 메시지 예:

> 이번에도 물리면 진짜 끝입니다. ...일단 반만 탑니다

### 9.3 애증은 불안정한 상태다

애증 상태에서는 수익이 나면 배신감이 풀려 충성으로, 손실이 나면 배신감이 1.5배로 올라 적대로 넘어간다. 플레이어에게 애증 봇은 "다음 리딩 한 번으로 갈리는 사람"이다.

애증 상태에서 수익이 났을 때의 배신감 감소량은 `수익률(%) × ambivalentRelief`(기본 1.0)이다. 20% 수익이면 배신감이 20 내려간다.

### 9.4 반드시 확인할 것

조사 Q4에서 수락 판정이 `신뢰도 − 배신감` 하나의 값으로 계산되고 있다면 9.2의 표로 교체한다. 교체 후 아래 테스트가 통과해야 한다.

- 신뢰도 80·배신감 80인 봇과 신뢰도 10·배신감 10인 봇은 차이가 둘 다 0이지만, 수락 확률과 투입 금액과 채팅 화행 분포가 서로 달라야 한다.
- 신뢰도 80·배신감 10인 봇과 신뢰도 80·배신감 80인 봇은 같은 리딩을 수락했을 때 매도 시점이 달라야 한다.

## 10. FOMO 태그, 기억 언급, 반복 방지, 언행일치

### 10.1 FOMO: 수치에서 상태 태그로

FOMO는 0\~100 수치를 없애고, 일정 시간 유지되는 상태 태그로 바꾼다. 탐욕과 공포는 수치로 유지한다.

**발동 판정.** 아래 두 사건 중 하나를 목격했을 때 판정한다.

- 다른 봇의 `BRAG`를 목격했고, 자신의 최근 수익률이 그 봇보다 낮다.
- 자신이 보유하지 않은 종목이 `fomoPriceTriggerPct`(기본 8%) 이상 급등했다.

```
FOMO 발동 확률 = (greed / 100) × (0.5 + suggestibility / 100) × (1 − fear / 150)
```

**발동 효과.** `fomoDurationMin`(기본 게임 20분) 동안 다음이 적용된다.

- 해당 종목의 추격 매수 확률이 크게 오르고, 투입 금액이 1.5배가 된다.
- 11장의 과열 제동을 무시한다.
- 닉네임 옆에 "FOMO" 태그를 표시한다.
- 발동 직후 메시지를 하나 올린다. 예) "지금이라도 타야 하나", "나만 없어 {symbol}"

**종료 후.** FOMO 중에 산 종목이 손실로 끝나면 `fear` +15, 수익으로 끝나면 `greed` +10을 준다. 종료 후 `fomoCooldownMin`(기본 게임 60분) 동안은 다시 발동하지 않는다.

**마이그레이션.** 기존 FOMO 수치를 읽던 코드(조사 Q3)는 모두 "FOMO 태그가 켜져 있는가"를 보도록 바꾼다. 기존 세이브의 FOMO 수치는 버린다. UI의 FOMO 게이지는 제거한다.

### 10.2 기억 언급

대상이 있는 메시지를 만들 때, 화자가 그 대상에 대한 기억(3.4)을 갖고 있으면 `memory` 변형 템플릿을 쓸 수 있다.

| 화행 | 쓰이는 기억 | 예시 |
| --- | --- | --- |
| `MOCK`, `REBUT` | `SAW_BRAG_THEN_CRASH`, `FOUGHT` | "@{target} {memWhen} {memSymbol} 자랑하다 반토막 난 분 아니신가" |
| `WARN_PLAYER`, `DOUBT`(플레이어 대상) | `LOSS_BY_LEAD`, `KICKED` | "저 그 방에서 {memSymbol}로 {amount} 날렸습니다" |
| `PRAISE_PLAYER` | `GAIN_BY_LEAD` | "{memWhen} {memSymbol} 때도 방장님 말 듣고 {memPct}% 먹었어요" |
| `REACT`(추방 목격) | `SAW_KICK` | "저번에도 한 분 나가시더니..." |

- `{memWhen}`은 경과 시간에 따라 "아까", "어제", "저번에", "지난달에" 중에서 고른다.
- 기억 하나는 최대 `memoryMaxUses`(기본 2)번까지만 언급한다. 같은 옛이야기를 반복하지 않게 한다.
- 기억 언급이 들어간 `MOCK`과 `REBUT`은 수신자의 `anger` 증가량을 1.3배로 한다.

### 10.3 반복 방지

- 봇 한 명은 자신의 최근 10개 메시지에 쓴 `templateKey`를 다시 쓰지 않는다.
- 방 하나의 최근 30개 메시지에 나온 `templateKey`는 누구도 다시 쓰지 않는다.
- 한 봇이 같은 화행을 연속 3번 쓰지 않는다. `ARGUMENT` 스레드 안의 `REBUT`, `MOCK`은 예외다.
- 후보 템플릿이 모두 막히면 그 차례에는 말하지 않는다. 반복하느니 침묵한다.
- 템플릿이 막혀 침묵한 횟수를 화행별로 집계해 디버그 로그에 남긴다. 이 수치가 높은 화행이 템플릿을 더 써야 할 곳이다.

### 10.4 언행일치

채팅은 시뮬레이션의 실제 상태와 어긋나면 안 된다. 플레이어가 채팅을 정보로 믿고 읽을 수 있어야 한다.

| 규칙 | 내용 |
| --- | --- |
| 행동 진술 | "샀다", "팔았다", "손절했다"는 최근 `actionClaimWindowMin`(기본 게임 30분) 안의 실제 매매 기록이 있을 때만 쓴다 |
| 보유 진술 | "들고 있다", "다 털었다"는 현재 보유 수량과 일치해야 한다 |
| 숫자 | 수익률, 금액, 평단가는 실제 값을 구어체로 반올림한 것이다. 부호가 뒤바뀌면 안 된다 |
| 자랑과 한탄 | `BRAG`는 해당 종목 또는 전체 수익이 플러스일 때만, `LAMENT`는 마이너스일 때만 쓴다 |
| 예고 | "살 거다", "손절할 거다"라고 말한 봇은 다음 매매 판단에서 그 행동의 확률을 2배로 한다 |

의도적인 거짓말은 이번 범위에 없다. 모든 메시지의 `isLie`는 `false`다. 나중에 고래 봇이 여론전을 할 때 이 필드를 쓴다.

## 11. 급관심종목 쏠림 수정

한 종목에 관심이 계속 몰리는 것은 "주목 → 매수 → 거래량 → 더 큰 주목"의 순환만 있고 이를 끊는 장치가 없기 때문이다. 먼저 원인을 측정하고, 아래 네 가지 제동 장치를 순서대로 넣는다. 이 장은 채팅 시스템과 독립적이라 언제든 별도로 작업할 수 있다.

### 11.1 먼저 측정한다

플레이어 없이 게임 3일을 돌리면서 아래를 기록한다. 수정 전과 후를 같은 시드로 비교한다.

| 지표 | 계산 | 목표 |
| --- | --- | --- |
| 1위 종목 거래량 점유율 | 게임 30분 창에서 1위 종목 거래량 ÷ 전체 거래량, 세션 평균 | 45% 이하 |
| 급관심 1위 교체 주기 | 급관심 목록 1위가 바뀌는 평균 간격 | 게임 60분 이하 |
| 최장 1위 유지 비율 | 한 종목이 1위였던 시간 ÷ 전체 시간 중 최댓값 | 25% 이하 |
| 봇 관심 분산 | 봇들이 마지막으로 거래한 종목의 종류 수 ÷ 전체 종목 수 | 50% 이상 |

목표값은 설정 파일에 둔다. 종목 수가 5개 이하이면 점유율 목표를 종목 수에 맞게 완화한다.

### 11.2 제동 장치 A: 급관심 산정 기준을 "평소 대비"로

가장 먼저 의심할 곳이다. 절대 거래량이나 절대 등락률로 순위를 매기면 한 번 뜨거워진 종목이 계속 1위에 남는다.

```
급관심 점수 = (최근 게임 5분 거래량 ÷ 그 종목의 최근 게임 3시간 평균 5분 거래량)
            × (1 + |최근 게임 5분 등락률(%)| / 5)
            × 체류 페널티
```

- **체류 페널티:** 목록에 연속으로 머문 시간이 게임 10분을 넘으면, 넘은 1분마다 점수를 5%씩 깎는다. 최소 0.3배.
- **재진입 대기:** 목록에서 빠진 종목은 게임 15분 동안 점수를 0.5배로 한다.
- 평소 거래량이 계속 높은 종목은 분모가 커져서 자연스럽게 목록에서 내려간다.

### 11.3 제동 장치 B: 봇의 관심 피로

봇마다 종목별 `fatigue`(0\~100)를 둔다.

- 그 종목을 거래하거나 그 종목에 대해 말할 때마다 `fatigueGainPerAction`(기본 8) 오른다.
- 그 종목을 건드리지 않는 동안 게임 1시간당 `fatigueDecayPerHour`(기본 15) 내려간다.
- 매매할 종목을 고를 때 그 종목의 선택 가중치에 `1 − fatigue/125`를 곱한다.
- 보유 중인 종목의 매도 판단에는 영향을 주지 않는다. 신규 진입과 추가 매수에만 적용한다.

### 11.4 제동 장치 C: 순환매

봇이 수익을 실현하면, 다음 종목을 고를 때 "아직 안 오른 종목"을 선호한다.

```
순환매 보정 = 1 + rotationStrength × (전체 종목 평균 등락률 − 그 종목 등락률) / 10
(0.3~2.5로 자른다. 등락률은 최근 게임 2시간 기준 %)
```

- `rotationStrength` 기본값은 1.0이다.
- 이 보정은 수익 실현 후 게임 60분 동안만 적용한다.
- 종목을 옮긴 봇은 메시지를 올릴 수 있다. 예) "{symbol} 익절하고 {symbol2}로 갈아탑니다". 이 메시지가 다른 봇의 관심을 새 종목으로 끌어 순환을 눈에 보이게 만든다.

### 11.5 제동 장치 D: 과열 제동

단기간에 많이 오른 종목은 신규 진입 확률을 낮춘다.

```
과열 보정 = max(0.2, 1 − (최근 게임 1시간 상승률(%) − overheatStartPct) / overheatRangePct)
```

- `overheatStartPct` 기본 15, `overheatRangePct` 기본 30. 15% 오르면 제동이 시작되고 39% 이상에서 최소값 0.2가 된다.
- 과열 종목을 보유한 봇은 `fear`가 게임 10분마다 2씩 오른다. 차익 실현 압력이다.
- FOMO 태그가 켜진 봇은 이 보정을 무시한다. 그래서 과열 구간의 마지막 매수자는 FOMO 봇이 된다.

### 11.6 적용 순서

A를 먼저 넣고 11.1의 지표를 다시 잰다. 목표에 못 미치면 B, C, D를 하나씩 추가하며 매번 측정한다. 한 번에 다 넣으면 어느 장치가 효과를 냈는지 알 수 없고, 시장이 너무 밋밋해질 위험이 있다.

가끔은 한 종목에 크게 쏠리는 일이 있어야 한다. 목표는 쏠림을 없애는 것이 아니라 쏠림이 끝나고 다른 종목으로 넘어가게 하는 것이다.

## 13. 디버그 도구와 검증

이 시스템의 품질은 가중치를 여러 번 고쳐 가며 올라간다. 그래서 "왜 이 말이 나왔는지"를 바로 볼 수 있는 도구와, 고칠 때마다 돌릴 수 있는 자동 검증을 먼저 만든다.

### 13.1 디버그 도구 (개발 빌드 전용)

| 도구 | 내용 |
| --- | --- |
| 메시지 추적 | 채팅 메시지를 누르면 동기, 후보 화행과 각 가중치, 선택된 템플릿 키, 채워진 슬롯 값을 보여준다 |
| 봇 상태 보기 | 봇을 누르면 성격 6종, 감정, 4분면 상태, `anger`·`affinity` 상위 5개 관계, 기억 목록을 보여준다 |
| 감정 변화 로그 | 모든 감정·관계·방 상태 변화를 `{시각, 대상, 필드, 이전값, 이후값, 원인 종류, 원인 ID}`로 기록한다 |
| 사건 로그 | 스레드 시작·종료, 분노 단계 변화, 퇴장, 동조 퇴장, 플레이어 조치를 별도 목록으로 기록한다 |
| 강제 명령 | 두 봇의 `anger`를 지정 값으로 설정, 특정 화행 강제 발화, 시드 고정 재시작 |

감정 변화 로그와 사건 로그는 정식 빌드에도 남긴다. 나중에 장마감 리포트가 이 두 로그를 읽어 "누가 왜 나갔는지"를 정리한다.

### 13.2 자동 시뮬레이션 테스트

화면 없이 시드를 고정해 실행하는 테스트 실행기를 만든다. 기본 조건은 봇 20명이 있는 리딩방 1개, 게임 24시간, 플레이어 조치 없음이다. 시드 5개로 돌려 아래를 확인한다.

**규칙 위반이 하나도 없어야 하는 항목**

| 번호 | 검증 |
| --- | --- |
| T1 | 같은 시드로 두 번 실행하면 메시지 목록이 완전히 같다 |
| T2 | 화면의 `@닉네임`과 `targetId`가 모든 메시지에서 일치한다 |
| T3 | 모든 자진 퇴장의 사건 로그에 1→2→3→4단계 기록이 순서대로 있다 |
| T4 | 메시지 하나로 분노 단계가 2단계 이상 오른 경우가 없다 |
| T5 | 모든 동조 퇴장 봇은 나간 봇에 대한 `affinity`가 60 이상이었다 |
| T6 | 동조 퇴장을 보고 또 나간 봇이 없다 |
| T7 | 방의 연속 30개 메시지 안에 같은 `templateKey`가 없다 |
| T8 | 행동·보유·숫자를 말한 모든 메시지가 그 시점의 실제 기록과 일치한다 |
| T9 | 채팅 목격만으로 `betrayal`이 오른 기록이 없다 |
| T10 | 퇴장했거나 채팅 금지 중인 봇이 호출되거나 말한 경우가 없다 |
| T11 | 스레드의 `turnCount`가 `maxTurns`를 넘은 경우가 없다 |

**범위 안에 들어와야 하는 항목** (범위는 설정 파일에 두고 튜닝하며 조정한다)

| 번호 | 지표 | 출발 범위 |
| --- | --- | --- |
| R1 | 호출 중 응답을 받은 비율 | 55\~80% |
| R2 | 스레드 평균 길이 | 2.5\~4.5턴 |

### 13.3 플레이어 조치 시나리오 테스트

같은 시드에서 조치를 한 경우와 하지 않은 경우를 비교한다.

| 번호 | 시나리오 | 기대 결과 |

| S2 | 첫 싸움을 끝까지 방치 | 퇴장 1명 이상. 퇴장 전에 `CALL_PLAYER`가 올라온다. 목격자의 `trust`가 내려간다 |

### 13.4 사람이 직접 확인할 것

자동 테스트는 규칙 위반은 잡지만 "재미있게 읽히는가"는 못 잡는다. 단계가 끝날 때마다 시드 3개의 채팅 로그를 게임 2시간 분량씩 텍스트 파일로 내보내고, 아래 질문에 답해 보고한다.

- 채팅만 읽고 퇴장한 봇이 왜 나갔는지 설명할 수 있는가?
- 연속된 두 메시지가 서로 관련 없어 보이는 곳이 얼마나 되는가?
- 같은 표현이 눈에 띄게 반복되는가?
- 한 봇의 말투가 시작부터 끝까지 같은 사람처럼 읽히는가?

## 14. 구현 순서

0단계부터 8단계까지 아홉 단계로 나눠 구현한다. 각 단계는 완료 조건을 통과한 뒤 커밋하고 다음으로 넘어간다. 앞 단계가 끝나면 게임은 항상 실행 가능한 상태여야 한다.

| 단계 | 작업 | 관련 장 | 완료 조건 |
| --- | --- | --- | --- |
| 0 | 기존 코드 조사와 보고서 작성. 코드는 고치지 않는다 | 2 | `docs/chat-social-audit.md`에 Q1\~Q13의 답, 대응표, 충돌 목록이 있다 |
| 1 | 데이터 모델 추가, 세이브 마이그레이션, 설정 파일 세 개, 로그, 자동 테스트 실행기 | 3, 12, 13 | 기존 세이브가 정상으로 불러와진다. 채팅 동작은 이전과 같다. T1 통과 |
| 2 | 네 단계 생성 파이프라인으로 교체. 기존 문구를 새 템플릿 구조로 옮긴다 | 4 | 모든 메시지에 `act`, `templateKey`, `debug`가 있다. T7, T8, R8 통과 |

| 4 | 화행별 감정 효과, 분노 단계, 자진 퇴장, 동조 퇴장 | 6, 7 | 장면 B가 발생한다. T3\~T6, T9, R4\~R6, S2 통과 |

### 단계마다 보고할 것

- 바꾼 파일 목록과 각 파일에서 한 일
- 통과한 검증 번호와 측정값. R 항목은 실제 수치를 적는다
- 이 문서와 다르게 구현한 부분과 그 이유
- 새로 추가했거나 기본값을 바꾼 설정 키

### 범위가 검증을 통과하지 못할 때

R 항목이 출발 범위를 벗어나면 코드가 아니라 설정 파일의 값을 먼저 조정한다. 조정한 키와 전후 값을 보고한다. 설정으로 해결되지 않으면 규칙 자체에 문제가 있다는 뜻이므로, 원인 분석과 규칙 변경 제안을 남기고 멈춘다.
