# 장 마감 세금·최초 손실 구제와 방 안 시계

2026-11-15. 사용자 확인: 첫 손실일의 **당일 실현손실만큼 한 번 보전**, 세금은 **당일 실현 매매이익만 0.05%**. 기존 회사 수익·회원료 정산과 1번 태블릿 정산 화면에 연결했다.

## 정산 규칙

- 당일 순실현손익은 기존 `PlayerProgression.RealizedProfit`에서 개장 시 누적값을 뺀 값이다. 기존 두 플레이어 계좌의 실제 매칭 이익·손실을 합산한다. 미실현 평가손익은 제외한다.
- 순실현손익이 양수면 세금은 `floor(순실현손익 × 0.0005)`원이다. 손실·본전에는 해당 장의 신규 세금이 없다. 이익 100만 원이면 세금 500원이다.
- 회사 수익·회원료·구제금은 과세하지 않는다. 거래대금이나 총자산의 0.05%를 떼는 방식이 아니다.
- 처음으로 당일 순실현손실을 기록한 마감에만 그 금액을 전액 보전한다. 부분 매도 원가로 소수 원 단위 손실이 생기면 구제금은 1원 단위로 올려 전액을 보전한다. 사용한 날짜를 계속 보관하며, 같은 날 재정산·저장 복구·이후 손실로 다시 받지 못한다.
- 실제 세금 납부는 기본 계좌의 예약금을 제외한 현금 및 당일 회사 수익·회원료·구제금에서 처리한다. 부족분은 미납 세금으로 다음 마감까지 보관한다. 현금을 음수로 만들거나 주식을 강제 매도하지 않는다.
- 미납액은 기본 계좌의 주문 가능 현금 및 순자산에서 차감한다. 2번 계좌 해금 판단과 기존 거래소 봇의 자산 관측에도 반영한다. 다음 날 미납액을 갚을 때 같은 금액을 신규 세금/당일 비용으로 다시 계산하지 않는다.
- 세금·구제금은 별도 현금 흐름이다. 실제 실현 매매손익, 리딩방 개설 실적, 봇의 실제 체결 가격·수량을 수정하지 않는다.

## 정산 화면

1번 태블릿 → 대시보드 → 정산.

- 상단: 정산 입출금을 크게, 마감 총자산을 보조 크기로 표시.
- 왼쪽 고정 열: 실현 매매손익, 회사 수익, 리딩방 이용료, 최초 손실 구제.
- 오른쪽 고정 열: 매매세 0.05%, 이전 미납, 이번 납부, 남은 미납.
- 하단: 당일 순손익, 기본계좌 현금, 구제 사용 여부/날짜와 최근 두 장의 요약.
- `정산 입출금 = 회사 수익 + 회원료 + 구제금 − 이번 납부`. 실제 매매손익은 이미 거래 중 계좌에 반영됐으므로 다시 입금하지 않는다.
- `당일 순손익 = 실현 매매손익 + 회사 수익 + 회원료 + 구제금 − 당일 신규 세금`.
- 숫자는 기존 고정폭 SDF 숫자 폰트, 한글 단위는 Pretendard SDF를 별도 열에 배치한다. 손실은 파랑, 수익은 빨강, 구제금은 절제된 청록색이다. 기존 Canvas·기기 위치와 입력 구조를 유지한다.

## 디지털 벽시계

- `TradeScene`의 기존 중앙 모니터 뒤, 뒷벽 상단에 `Area :: Market Wall Clock` 프리팹 인스턴스 하나를 추가했다. 중앙 차트 Canvas 중심의 X, 월드 Y 7.05, 뒷벽보다 앞쪽 0.15 위치다. 기존 기기와 카메라 Transform은 변경하지 않았다.
- 검은 하우징 약 1.9×0.64×0.16, 4자리 7세그먼트와 콜론으로 **HH:MM만** 표시한다. 숫자는 Canvas나 이미지 조각 대신 176정점 메시 하나와 점등/소등 두 재질이다.
- `MarketDayController.GameMinute`를 그대로 읽는다. 일시정지하면 시계도 멈추고, 분이 달라질 때만 메시 인덱스를 갱신한다. 별도 시간 누적이나 배속 기능은 없다.
- URP Lit 재질의 붉은 자체 발광과 별도의 작은 실시간 Point Light를 사용한다. 발광만으로 실시간 GI가 생긴다고 가정하지 않았다.
- 조명: 빨강 `(1, 0.065, 0.025)`, 강도 0.35, 반경 1.7, 그림자 없음, 반사광 강도 0. 숫자 발광은 `(1.6, 0.018, 0.005)`. 전역 Bloom·노출·주변 조명을 변경하지 않았다.
- 최초 촬영에서 URP의 재질 검증이 `_EMISSION`을 끄는 문제가 확인됐다. URP 패키지의 `BaseShaderGUI`가 `AnyEmissive` 플래그로 키워드를 정하는 것을 확인하고 RealtimeEmissive 플래그를 사용해 저장·재임포트 후에도 유지되도록 수정했다. 별도 GI 베이크는 하지 않는다.
- 같은 프레임의 조명 ON/OFF 캡처를 비교해 벽 패치의 붉은 채널이 평균 약 11.4/255, 최대 61/255 증가하는 것을 확인했다. 실제 주변 벽에 국소적으로 빛이 닿는다.

## 검증 결과

- 순수 원장 **271회 통과**. 200회는 연속 일일 마감 반복 검사다. 이익/손실/본전, 원 미만 세금, 첫 구제/재구제 차단, 부분 원가의 소수 원, 중복 정산, 미납 이월과 재납부, 부채 포함 자산, 손상된 저장 데이터 거절을 포함한다.
- 실제 Unity 씬 **52항목 통과**. 실제 주문 매칭으로 +100만 원 → -200만 원 → -100만 원의 세 장을 만들고, 세금 500원 → 최초 구제 200만 원 → 재구제 없음과 실제 계좌 입금을 확인했다. 손실일 실제 봇 회원료 3만 원도 과세에서 제외됐다.
- 1600×900과 1920×1080에서 수익 정산·첫 손실 구제·다음 손실 정산 및 방 시계를 촬영·확인했다. TMP 잘림·누락 글리프 없음. 조 단위 음수 금액을 넣는 별도 레이아웃 검사도 통과했고 셀 크기·위치가 유지됐다.
- 정산 열기·닫기는 실제 게임 카메라 좌표의 UI 레이캐스트로 확인했다.
- 시계 중복 없음, HH:MM 연동, 일시정지 동기화, 재임포트 후 자체 발광 키워드 유지, 그림자 없는 국소 조명을 확인했다.
- 최종 Unity 실행: CPU **한 코어 / BelowNormal / 20fps**, 최대 **2,438 MiB**, **117.8초**, 종료 코드 0. 다른 Unity/게임/활성 컴파일이 있으면 시작하지 않는 가드와 4GB/240초 중단 예산을 유지했다. 실행은 겹치지 않았다.
- 마감 검증은 테스트 드라이버가 장의 경과 타이머를 끝으로 이동해 실제 마감 코루틴을 실행했다. 장기 자연 관전 테스트가 아니며 제품에 배속 기능을 넣지 않았다.
- 임시 Unity 테스트 드라이버는 `Validation/TaxClock/capture-driver.cs.txt`로 보관하고 Assets에서 제거했다. 이후 런타임·에디터 전체 C# 컴파일 성공. 배포용 플레이어 빌드는 생성하지 않았다.
- 기존 `Trader`, `OrderBook`, `MarketDayController`, `PlayerProgression` 스크립트가 작업 전과 바이트 단위로 동일함을 확인한다.

최종 원본 캡처·로그: `Validation/Screenshots/2026-11-15-tax-clock-02/`. `light-comparison.json`은 조명 ON/OFF 픽셀 비교 결과다.

## 저장 범위

일일 정산 저장 조각은 버전 2로 확장했다. 버전 1은 소급 세금 없이 읽으며, 구제 사용 날짜와 미납액은 복구 시 보존된다. 기존 프로젝트의 전체 월드 디스크 저장/재시작 복구 기능은 여전히 별도 과제다. 이번 변경이 전체 게임 저장 기능을 완성한 것은 아니다.
